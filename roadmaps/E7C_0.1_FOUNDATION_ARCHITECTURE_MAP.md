# E7C/0.1 foundation architecture map

## 1. Purpose

This document provides the whole-system mathematical picture required before a
calculus is specified. It connects the published v0.12.1 baseline, later
non-canonical profiles and proposals, the proposed E7C nucleus, derived
mathematics, executable witnesses, empirical evaluation and product consumers.

It does **not** settle the open decisions, prove consistency, define a complete
formal grammar, canonise a successor kernel or authorise product migration.

## 2. Authority stack

| Layer | Authority | May determine | Must not determine |
|---|---|---|---|
| Published baseline | v0.12.1/RGP2 | Current experimental canonical E7G-T meaning | Automatic E7C primitives or product migration |
| Successor research | v0.13/WPC, v0.14/REC, MSC and other proposals | Candidate constructions and counterexamples | Canonical status by version or merge alone |
| Gap/proposal control | Gap register and successor manifest | What must be evaluated and dispositioned | Mathematical validity |
| E7C charter/specification | Reviewed WP1–WP4 documents | Proposed shared calculus and theorem obligations | Empirical effectiveness or domain truth |
| Adapters | Reviewed profile translations | Relationship between one source fragment and E7C | Silent reinterpretation of the source |
| Empirical protocols | REC-EVAL and future pilots | Measured behaviour under frozen procedures | Calculus semantics |
| Products | E2CI, E7Q, Boundary, E7DB and later consumers | Product-local guarantees and value | Kernel or foundation meaning |

## 3. Five-plane architecture

### Plane A — constitutional declaration

Declares the objects relative to which a judgement is meaningful:

- entity and identity;
- description and configuration;
- carrier and admitted domain;
- context, inquiry and equivalence criterion;
- scope, rank and temporal frame;
- authority and access;
- source/profile/model editions;
- resource bounds.

This plane is declarative. It does not execute a term or assert external truth.

### Plane B — constructive calculus

The proposed E7C nucleus supplies:

- typed terms and declarations;
- composition and controlled binding;
- exact finite values where declared;
- partial operations with explicit domains;
- views and loss;
- reconstruction;
- histories;
- tagged outcomes;
- static effects;
- deterministic bounded evaluation;
- canonical witnesses.

Only concepts required by more than one source fragment without semantic
distortion should enter the nucleus.

### Plane C — derived mathematical libraries

Profile-neutral constructions that can be defined from the nucleus belong here
unless non-definability or unacceptable loss is demonstrated. Candidates
include:

- phase classification;
- reconstruction-fibre analysis;
- relational non-separability;
- compatible-family and obstruction analysis;
- selected quotient and invariant constructions;
- bounded realisation strategies.

Derived status is preferred to primitive status because it reduces the trusted
semantic base.

### Plane D — source-profile adapters

Adapters connect bounded source fragments to E7C while preserving source
identity and status:

- EEC-Q;
- SF;
- CFS;
- RGP;
- WPC Core;
- WPC Evolution;
- WPC Distributed, if ever supported;
- REC;
- MSC;
- temporal and operational-phase profiles.

Each adapter has exactly one disposition:

1. `faithful_embedding`;
2. `faithful_interpretation_with_explicit_loss`;
3. `partial_translation`;
4. `unsupported`.

A component-level retain/adapt/replace/retire governance decision is separate
from this mathematical adapter disposition.

### Plane E — evidence and applications

This plane includes:

- conformance fixtures;
- proof and counterexample artefacts;
- independent witness checking;
- empirical protocols;
- application pilots;
- product-local policies and runtimes.

Passing upward from a product result to a mathematical or canonical claim is
forbidden without the corresponding review gate.

## 4. Ontological separation

The initial ontology must keep the following sorts or indexed families
distinct:

| Concept | Meaning | Must not collapse into |
|---|---|---|
| `Entity` | Object of modelling under an identity discipline | Description or configuration |
| `Description(E)` | Representation about entity E | E itself |
| `Configuration(E,C,t)` | Admitted arrangement under context and time | Formal state or family |
| `State_Q(A)` | Exact formal combination over carrier A | Probability, evidence or quantum amplitude |
| `Family(A,D)` | Admitted alternatives with declared dependence | Linear combination |
| `View(S,I)` | Inquiry-relative accessible representation retaining source reference | Source, encoding or reconstruction |
| `Encoding(S,K)` | Material representation under an encoding contract | View or semantic whole |
| `Whole(P,C)` | Semantic whole under constitution contract C | Constitutive presentation P |
| `Occurrence(a,W)` | A constituent occurrence participating in W | Free-standing object a |
| `Scope` | Declared locus of a construction or claim | Rank, time or authority |
| `History(A)` | Ordered transformations and outcomes | Final value alone |
| `Evidence(c)` | Typed support/refutation input for claim c | Truth or decision authority |
| `Witness(J)` | Replay material for a claimed derivation J | Proof of source truth |
| `Outcome(A)` | Success or typed non-success of a computation | Empty value |

Indices may be refined or replaced during WP1/WP2, but the distinctions cannot
be removed without a reviewed counterexample and migration analysis.

## 5. Proposed judgement family

The minimum judgement architecture is:

```text
Delta; Gamma; Phi |- t : A ! epsilon
Delta; Gamma; Phi |- t defeq u : A
Delta; Gamma; Phi; M |= t deneq u : A
Delta; Gamma; Phi; I |= t obseq u : A
Delta; Gamma; Phi; kappa |= x phaseeq y
Delta; Gamma; Phi |- t downarrow o ; lambda ; w
Delta; Gamma; Phi |- w checks J
```

where:

- `Delta` contains profile, model, schema and rule editions;
- `Gamma` contains typed variables, entities and admitted declarations;
- `Phi` contains scope, inquiry, access, authority, time and resource
  constraints;
- `epsilon` is the static effect;
- `M` is a declared denotational model;
- `I` is an observation/inquiry contract;
- `kappa` is a phase criterion;
- `o` is a terminal outcome;
- `lambda` is the runtime effect/loss ledger;
- `w` is a canonical witness.

Notation remains provisional. The separation of judgements is not provisional.

## 6. Outcome algebra

The first bounded outcome family is:

```text
Outcome(A) =
    success(A, Witness)
  | invalid_input(Diagnostic)
  | type_error(Diagnostic)
  | domain_error(Diagnostic)
  | unsupported(Capability)
  | undetermined(Reason)
  | resource_limit(ResourceLedger)
```

Required rules:

1. Empty, false, zero and no-candidate results are values only when the
   operation's codomain says so.
2. A finite exhaustive reconstruction may return an empty fibre successfully.
3. An incomplete search returns `undetermined` or `resource_limit`, not a
   successful partial fibre.
4. No non-success tag can be converted silently into an empty successful value.
5. Every terminal outcome retains its incurred ledger and remains bounded by
   the term's static effect.
6. Composition rules must specify whether and how later steps execute after
   each outcome.

## 7. Effect architecture

Candidate effect dimensions are:

| Effect | Records |
|---|---|
| `Partiality` | Domain checks and failure possibility |
| `Loss` | Information intentionally discarded or unavailable |
| `Inquiry` | Observation/equivalence criterion dependence |
| `Access` | Visibility and decoding capabilities used |
| `Authority` | Permissions or decision powers relied upon |
| `Alternatives` | Dependence-preserving family operations |
| `Evidence` | Evidence admission, polarity and reliance |
| `History` | Ordered change and temporal reliance |
| `Resource` | Finite bounds and interruptions |
| `Bridge` | External model, system or empirical assumption |

WP1 must decide whether the carrier is a product lattice, graded algebra,
row-polymorphic effect system or another construction. Until then, the
requirements are:

- a declared preorder or refinement relation;
- explicit sequential and parallel composition;
- monotonic accumulation unless a justified discharge rule exists;
- a distinction between incurred, relied-on and merely possible effects;
- static bounds for every terminal outcome;
- canonical serialization in witnesses.

## 8. Equality and comparison ladder

No single equality symbol may serve all levels.

| Level | Relation | Intended use |
|---|---|---|
| 1 | Exact identity | Same canonical object and edition |
| 2 | Definitional equality | Decidable type-checker conversion |
| 3 | Denotational equality | Same meaning in a pinned model |
| 4 | Isomorphism | Structure-preserving invertible correspondence |
| 5 | Observational equivalence | Indistinguishable under declared observations |
| 6 | Phase equivalence | Same inquiry-relative phase criterion |
| 7 | Representation agreement | Consistent materialisations under a contract |
| 8 | Reconstruction compatibility | Members of the same declared fibre |
| 9 | Empirical similarity | Measured performance relation, not formal equality |

Required directionality:

- definitional equality must imply denotational equality in admitted models;
- the converse is not assumed;
- observational or phase equality cannot be used for type conversion;
- adapter faithfulness must state which source relation is preserved and
  reflected;
- lossy adapters must name the quotient or abstraction relation.

## 9. Core operation families

The candidate nucleus should be tested around these generic operation families:

| Family | Generic role | Profile-specific material excluded from core |
|---|---|---|
| Admission | Establish well-formed typed input | Domain truth |
| Composition | Build typed constructions | One profile's whole semantics |
| Map/transform | Apply total or partial typed operation | Unchecked host-language code |
| View | Produce inquiry-relative access with loss | Encryption or material encoding |
| Encode/decode | Relate semantics to representation | Cryptographic guarantees |
| Restrict | Narrow an admitted family explicitly | Silent filtering |
| Reconstruct | Compute or describe a source fibre | Claim of unique source without proof |
| Quote/pack | Reify an inert construction | Automatic evaluation or security |
| Evaluate-inside | Controlled transformation of quoted content | Ciphertext computation by metaphor |
| History | Preserve ordered operations and outcomes | Final-state-only identity |
| Classify | Apply declared criterion to admitted candidates | External truth |
| Witness | Record replayable derivation | Trusted source validity |

## 10. Source-to-foundation disposition map

| Source component | Provisional mathematical placement | Reason |
|---|---|---|
| Constitutional envelope and boundary discipline | Core indices/declarations | Shared context for every judgement |
| Typed outcomes and partial domains | Core | Required for composition safety |
| Source/View/Preserve/Lose | Core plus derived reconstruction | Cross-profile and product relevance |
| Exact canonical identity | Core infrastructure | Required for editions and witnesses |
| Histories and operation order | Core | Outcomes and identities can be path-sensitive |
| EEC-Q rational formal sums | Adapter/library | Specific algebra; not universal value semantics |
| SF dependence-preserving families | Adapter with possible generic family library | Dependence is reusable; realisation policy is not necessarily core |
| CFS family-of-state nesting | Adapter/derived composition | Must preserve nesting direction |
| RGP/0.2 generation, projection and source retention | Adapter from the pinned v0.12.1 component plus derived recursive library | Recursion and local reconstruction need bounds; v0.13 adaptation requires a differential |
| WPC/0.1 whole–portion coherence | Preserved predecessor adapter | The v0.12.1-to-v0.13 bridge must not disappear behind WPC/0.2 |
| WPC Core/0.2 | Adapter/derived whole-part library | Strong constitution semantics are not universal composition; extension over WPC/0.1 must be explicit |
| WPC Evolution | Independent optional adapter | Partial evidence and authority/history questions |
| WPC Distributed | Unsupported/deferred | Requires distributed-systems semantics |
| REC | Adapter/applied library | Evidence status is not universal truth semantics |
| MSC | Derived finite diagram library if conservative | Candidate generic local-to-global analysis |
| Relational non-separability | Derived predicate if definable | Avoid primitive proliferation |
| REC-EVAL | Empirical plane only | Evaluates utility, not mathematical meaning |

All placements remain provisional until WP0 disposition and later semantic
proofs. “Core” means candidate nucleus, not approved implementation.

## 11. Composition picture

A conformant bounded computation should have this abstract shape:

```text
Pinned declarations
  -> admission and typing
  -> static effect bound
  -> deterministic bounded evaluation
  -> terminal outcome + runtime ledger
  -> canonical witness
  -> independent replay
  -> optional profile comparison
  -> optional empirical/application evaluation
```

At each arrow, failure is typed and retained. No later stage upgrades the claim
strength of an earlier stage.

## 12. Witness trust boundary

A witness must bind at least:

- calculus and profile editions;
- schema and rule editions;
- source identities and hashes;
- context, inquiry, scope and temporal frame;
- access and authority assumptions;
- admitted domains;
- operation order;
- intermediate identities or sufficient replay data;
- terminal outcome;
- runtime effect/loss ledger;
- resource bounds;
- adapter and equality criteria used.

The independent checker establishes replay relative to these pins. It does not
establish external truth, authority legitimacy, scientific validity, security
of an external system or empirical effectiveness.

## 13. Proof programme dependency graph

The intended dependency order is:

1. syntax and decidable formation;
2. admission and typing;
3. definitional equality and conversion;
4. operational outcomes and ledgers;
5. denotational interpretation;
6. substitution and structural lemmas;
7. determinism for the declared fragment;
8. type preservation;
9. effect/ledger soundness for all terminal outcomes;
10. declared progress;
11. reconstruction soundness and bounded completeness;
12. witness replay soundness;
13. adapter preservation and reflection;
14. lowering adequacy;
15. derived-library theorems.

Mechanisation begins only after a proof-assistant spike tests the hardest
representative obligations. Proof status must use the mandate's controlled
vocabulary.

## 14. Empirical and product decision

After the foundation and representative adapters exist, continuation is decided
by evidence:

| Result | Consequence |
|---|---|
| Foundation unsound or unimplementable | Preserve product development on v0.12.1/profile-local contracts |
| Sound but not useful | Keep as research; no migration |
| Useful for selected components | Hybrid architecture through explicit adapters |
| Conservatively stronger and operationally beneficial | Plan reviewed component-level migrations |
| Different results by product | Product-specific adoption; no forced ecosystem-wide runtime |

The likely architecture is layered rather than an all-or-nothing replacement:
E7C may supply a small verified base while v0.12.1 and later profiles remain
versioned mathematical languages above it.

## 15. Open foundation decisions

WP0/WP1 must not conceal these choices:

1. What is the minimal profile-neutral core?
2. Which declarations belong in `Delta`, `Gamma` and `Phi)?
3. Is the context structural, linear, affine or mixed?
4. What is the effect carrier and composition algebra?
5. Which outcomes are core and which are profile extensions?
6. What finite carriers and recursion are decidable in E7C-B1?
7. What is definitional equality?
8. Which denotational models are required initially?
9. What observations define adapter reflection?
10. How are source references represented without granting access?
11. How are authority and time scoped and revoked?
12. Which witness facts are trusted inputs versus replayed derivations?
13. Can MSC and non-separability be derived without new primitives?
14. What quotient precisely licences each lossy adapter?
15. Which v0.13+ proposals are deferred, and what evidence would reopen them?

## 16. Initial vertical slice

The first slice remains deliberately small:

1. admit two finite configurations;
2. construct one exact rational formal state through an adapter;
3. apply a strict partial map;
4. produce a lossy view with source reference;
5. compute the complete bounded reconstruction fibre;
6. classify the fibre under a declared phase criterion;
7. return a typed terminal outcome and bounded ledger;
8. serialize a witness;
9. replay it in an independent checker.

It must include positive, empty, ambiguous, domain-error, unsupported and
resource-limit cases. It must not include WPC Evolution, WPC Distributed, REC
decision policy, unbounded recursion, quantum execution or product migration.

## 17. Completion boundary

This architecture map is complete as a **picture** only when the successor
manifest and gap register cover the WP0 cutoff. It is complete as a
**foundation specification** only after WP1–WP4 define the syntax, semantics and
proofs. It is effective only after independent replay, adapter differentials and
application pilots.
