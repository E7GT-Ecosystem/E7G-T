# E7C/0.1 implementer handoff

**Edition note (2026-09-25):** This handoff was pinned to v0.12.1 at its
original baseline. v0.15/MSC1 now governs new source citations, while
existing E7C builds retain their pins and open implementation proof links.
This is the original WP0 handoff and must not be used to restart WP0.
New milestones follow
[`E7C_0.1_V015_ACTIVE_BUILD_MAP.md`](E7C_0.1_V015_ACTIVE_BUILD_MAP.md)
and the current E7C state ledger.

## 1. Assignment

Begin the **E7C/0.1 Foundation** research programme defined in:

`roadmaps/E7C_0.1_FOUNDATION_BUILD_MANDATE.md`

Do not begin implementation from this handoff alone. Read the complete mandate,
the repository instructions, the post-v0.12.1 gap and proposal register and the
pinned source materials first.

Your initial assignment is **WP0 — Baseline and Decision Register**, followed by
the charter portion of WP1. You are not yet authorised to stabilise the E7C
language, implement the vertical slice, alter an existing E7G-T profile or
modify the canonical kernel.

### 6.1 Source registry

For every relevant artifact record:

- repository and path;
- profile/version identifier;
- canonical, candidate, proposal or open-PR status;
- exact commit and SHA-256 where available;
- governing conformance matrix;
- implemented subset;
- known consumers;
- visibility or provenance limitation;
- the gap or proposal entries supported by the artifact.

### 6.2 Required component disposition matrix

Cover at least EEC-Q, SF, CFS, RGP, WPC and REC. Also give MSC,
non-separability and REC-EVAL their correct non-core dispositions.

Each component row must contain:

- exactly one of `retain`, `adapt`, `replace`, `retire`;
- source identity and immutable pin;
- preservation;
- loss or semantic change;
- ID impact;
- data/schema impact;
- API impact;
- compatibility check;
- affected consumers;
- decision authority/status.

The present default is **retain** unless a reviewed reason establishes
otherwise. This handoff does not authorise replacement or retirement.

### 6.3 Terminology matrix

At minimum distinguish:

- entity / description / configuration;
- configuration / formal state / family;
- view / projection / encoding / materialisation;
- whole / portion / compatible multi-scope family;
- exact identity / definitional equality / denotational equality / isomorphism
  / observational equivalence / phase equivalence;
- domain failure / unsupported / undetermined / resource limit;
- evidence polarity / information status / source truth / decision authority;
- rank / scope order / time / access / authority.

### 6.4 Decision register seed

Record, without silently settling, at least:

1. context/resource discipline: ordinary, linear, affine or mixed;
2. definitional equality and permitted conversion rules;
3. model-relative denotational equality;
4. effect carrier, preorder and composition;
5. strict versus filtering partial operations;
6. finite reconstruction completeness;
7. witness trust base and edition pins;
8. abstract versus E7C-B1 recursion boundary;
9. core primitive admission rule;
10. profile adapter conservativity criteria.

### 6.5 Post-v0.12.1 gap and proposal register

Regenerate the successor-source coverage manifest against the exact WP0 commit
and timestamp, then expand the roadmap seed into a source-complete, reviewed
decision surface. For
each originating-author suggestion, alternate successor draft, counterexample,
review finding or product discovery, record the demonstrated gap, semantic
effect, dependencies, compatibility evidence, proposed destination and open
obligations. Preserve rejected and superseded ideas so they cannot return under
new names.

Coverage must explicitly include v0.13, every later kernel draft, release
manifest, standalone package, merged or open proposal and empirical companion.
Versionless, v0.12.x-labelled, rejected and superseded additions remain in
scope.

Do not infer completeness from the visible repository tree. Search issues, PRs,
review records and recoverable source artifacts. Record any missing source or
visibility limit explicitly. The accepted verdict is exactly
`complete_for_initial_foundation_slice` or
`complete_with_named_deferrals`; `incomplete_seed_inventory` blocks the
implementation slice.

## 7. WP0 acceptance gate

Do not begin WP2, WP3 or runtime implementation until a reviewer confirms:

- all sources are pinned and correctly dispositioned;
- the component matrix uses `retain`, `adapt`, `replace` or `retire` explicitly;
- preservation, loss and ID/data/API impact are stated;
- existing profile meanings and consumers are not silently migrated;
- open PRs are not represented as merged policy;
- v0.12.1 remains canonical;
- no private or unpublished collaborator material has entered public guidance;
- every known post-v0.12.1 proposal has a reviewed register entry and destination;
- every v0.13-and-later or otherwise non-canonical successor artifact through
  the WP0 cutoff has an immutable manifest pin and mapped disposition;
- the gap register has an accepted completion verdict.

Neutral WP1 vocabulary may be drafted while proposal discovery continues. WP2,
WP3, the executable vertical slice and further product-semantic milestones
remain blocked until the accepted verdict is recorded.

## 8. Bounded WP1 charter work

After WP0 is internally complete, draft—but do not yet freeze—the E7C charter:

- purpose and non-goals;
- judgement forms;
- separation of definitional, denotational and phase equality;
- initial type families;
- effect categories;
- outcome taxonomy;
- core-versus-library admission principle;
- abstract-calculus versus E7C-B1 boundary;
- theorem statement inventory;
- compatibility posture.

The charter must incorporate these reviewed corrections:

1. definitional equality is separate from model-relative denotational equality;
2. effects require a preservation/ledger-soundness theorem;
3. successful finite reconstruction requires exact fibre completeness;
4. adapter conservativity must preserve and reflect relevant distinctions, or
   be explicitly relative to a named quotient;
5. REC translations and witnesses bind provenance/dependence groups, source,
   model edition and decision policy;
6. implementation follows reviewed slice-specific static, dynamic and
   denotational semantics and a reviewed witness contract.

## 9. Explicitly unauthorised work

Do not yet:

- amend or prematurely canonise the v0.12.1 canonical file;
- treat v0.12.1 as an exhaustive source for E7C while known gap-filling proposals
  remain undispositioned;
- declare v0.15 or v1.0;
- replace profile identifiers, schemas or APIs;
- merge WPC, REC or MSC meanings into one undifferentiated operator;
- implement a large parser, runtime or compiler;
- stabilise E7C syntax or IR;
- claim general consistency, completeness or novelty;
- claim empirical reasoning improvement;
- interpret EEC-Q coefficients as probabilities, evidence weights or quantum
  amplitudes;
- import product-specific legal, medical, translation or quantum semantics into
  the core;
- execute arbitrary host-language strings;
- treat passing first-party tests as independent reproduction.
