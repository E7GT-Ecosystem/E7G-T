# Start Here — E7G-T v0.12 Experimental

E7G-T now treats two questions as parts of one modelling problem:

1. **How is the thing constructed, transformed, represented, projected, or reconstructed?**
2. **Which differences matter for the inquiry, and when has a material operational boundary been crossed?**

## Thirty-second explanation

A representation can hide two different kinds of uncertainty:

- **source uncertainty:** several richer sources may produce the same visible view;
- **phase uncertainty:** those possible sources may belong to materially different operational phases.

E7G-T therefore does not stop after saying “the view is not the source.” It also asks:

> Do all admitted sources compatible with this view support the same operational classification?

## Minimum workflow

```text
1. Name the modelled entity.
2. Separate semantic context from the inquiry.
3. Declare the operational boundary.
4. Identify the current configuration or view.
5. State what is preserved and lost.
6. Define what counts as the same phase for this purpose.
7. Classify, abstain, return to source, compare paths, or stop.
```

## Three practical profiles

### E7-Line

Use for immediate orientation when the basis is obvious.

```text
For <inquiry>, treat <subject> as <view/configuration> under <context>.
Preserved/lost: <summary>.
Same phase while: <protected condition>.
Assessment: <same/different/undetermined/not applicable>.
Next move: <action>.
```

### E7-Check

Use for routine QA, software review, document analysis, dashboard inspection, or AI-output review.

### E7-Analysis

Use for consequential decisions, disputed classifications, reusable methods, cross-context work, formalisation, or publication.

## Fast route choice

| Question | Route |
| --- | --- |
| What is being projected? | Extensional–projective |
| What did the view lose? | Extensional–projective |
| Which source configurations remain possible? | Extensional–projective reconstruction fibre |
| Which configurations count as equivalent? | Operational phase |
| Did this edit cross a material boundary? | Operational phase |
| Can this view support a readiness classification? | Combined |
| Does one operation work for every member of the phase? | Operational phase with representative check |

## Optional executable profiles

Use **EEC-Q/0.1** when exact finite formal combinations and typed transformations are material. Use **SF/0.1** when a finite symbolic description must retain a potentially infinite family of possibilities and an explicit realisation rule. Use **CFS/0.1** when each member of that outer family must be a complete formal state. Ordinary E7G-T analysis does not require these profiles.

## First exercise

Take an AI-generated answer that recommends an action.

1. Identify the visible answer and its declared sources.
2. List at least two source configurations compatible with the answer.
3. Define the reliance phases relevant to the inquiry, such as `draft-only`, `source-supported`, and `validated-for-use`.
4. Determine whether every compatible source configuration lies in the same phase.
5. If not, require source return or another view.
