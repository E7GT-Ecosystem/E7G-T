`E7CEECQTwoStageOperational.lean` models the actual charge precedence for a
bounded ordered event plan: each attempted event first requires an available
step, consumes one step, then requires ledger space to append the event.
Events are first restriction attempt, one event for each admitted first-stage
row, second attempt only after successful first-stage traversal, and one
event per first-retained row. Unsupported and undetermined interpretations
stop immediately after their respective attempt event. The typed terminal
constructors are disjoint: `success Partition`, `resourceLimit Progress`,
`unsupported Stage`, `undetermined Stage`.

Let `m` be the admitted input row count, `n` the number without first-stage
AB, and `N = 2 + m + n` the complete ready-policy event count. A completed
ready-policy success requires both bounds at least `N`; the Lean theorem
`sufficient_budgets_produce_partition` returns the exact mathematical
three-way `source` partition. `full_success_agrees_with_recursive_partition`
then applies PR #102's independent row-scan equality. `exhaustion_returns_prefix`
states that if a bound is short, the only terminal is `resourceLimit` with
the ordered event prefix of length `min(stepBound, ledgerBound)` (capped by
the plan). Step progress equals the completed event count if the step bound
stops the run; when ledger space stops it, the failed append has already
consumed one extra step. Progress separately carries completed first-stage
exclusions, if available, and the prefix of second-stage exclusions. A
resource terminal has no completed partition payload.

The associated Python tests calculate an independent event plan directly
from admitted Joint rows and compare whole source replay with independent IR
execution: terminal, exact rational portions, ordered ledger, completed
steps and stage-specific partial progress. Tests cross first and second
unsupported/undetermined paths with step and ledger exhaustion; the same
marginals/different Joint controls and signed coefficients remain in the
#101 and #102 regression gates.

**External correspondence premises, not theorems:** a bijective encoding of
all Python-admitted graph tags and canonical rows into Lean `Graph`/`Row`;
equality of Python/Lean normalized exact rational coefficients and ordered
Joint support; stage-specific policy/edition agreement; ledger row-key
serialization; child witness and IR-package admission; Python and IR
implementations refining the Lean event plan for every admitted input.
Finite replay tests challenge these premises, but do not prove the general
implementation relation or EEC-Q semantic adequacy. This branch changes no
published source, B1/B2/B3 grammar, profile adoption or product API.
