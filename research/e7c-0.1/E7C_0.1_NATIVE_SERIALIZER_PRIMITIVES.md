## Actual native observations

The unchanged helper function code runs in an isolated single-thread process.
Forwarding attribute hooks call the original `object.__getattribute__` once,
at the executing helper's bound receiver. They retain actual edges/tag,
numerator/denominator and arity/terms results. A forwarding list hook calls the
original native constructor once on the exact tuple just returned by the
running edge read. Every destination cell must be the same object as its
corresponding operand cell. Logical tokens retain order and repeated objects;
they are not machine addresses or C pointer/refcount proofs.

Native helper call/return callbacks bind each `_row` argument to the next
actual observed term, and each `_graph` argument to the next actual coordinate.
Missing, repeated or rebound reads, operands and calls reject. Snapshots do not
provide post-execution replacement operands. No expected semantic partition,
helper output or Lean row plan is consulted by the observer. A returned packet
still requires kernel checking.

Hooks, list binding, profiler and lock are restored on normal and exceptional
exits. Existing instrumentation and overlapping capture are refused. Initial
and final source/code/object bindings and input snapshots are checked. Those
checks do not prove arbitrary host stability between observations. The adapter
caps retained rows/events/bytes and coefficient/snapshot domains; it does not
bound native peak memory, CPU, allocation or wall time. Native exceptions and
interruptions produce no successful packet; they are not relabelled as proved
E7C product outcomes.

## Kernel receipt

`E7CJointNativeSerializerCapture.Certificate` checks four obligations for the
reported literals: executable selected-source result, primitive/frame ledger,
each copy's ordered cell-token equality, and the complete copy count. It yields
the existing serializer statement trace, exact encoded output, schema fuel and
unique keys. Copies preserve one stable token interpretation pointwise. For n
rows, the declared ledger has 16n+4 entries and there are 2n copies.

The exporter retains actual observed input/output/events and copy tokens. It
validates only literal domains, shape and evidence limits. Semantically forged
reports are exported unchanged for Lean to reject. A valid receipt establishes
mathematical agreement of these literals, not the provenance of an arbitrary
caller-supplied packet. This format is opt-in experimental research evidence.
