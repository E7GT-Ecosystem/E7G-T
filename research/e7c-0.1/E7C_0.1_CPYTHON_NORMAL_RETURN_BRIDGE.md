# CPython-to-modeled normal-return bridge

## Status and scope

This is a bounded, conditional bridge for the selected `admit` normal-return
path in `e7c_eecq_joint_restrict_b1.py`. It starts from an already decoded
`List WireRow` and ends at the #138 `ModeledNormalExecution` trace. It does not
interpret raw JSON, prove all CPython semantics, cover exception/resource
paths, or establish the independent IR or second-stage links.

The new Lean result is
`E7CJointAdmissionCPythonBridge.pinned_normal_return_yields_modeled_trace`.
Given separate operation outcomes and the pinned normal-return control-flow
fact, it constructs #138's modeled trace. Composing with
`pinned_normal_return_exact_rows` gives exact ordered typed rows, including
both correlated coordinates, tags and rational coefficients.

## Operation premises

The Lean structure `CPythonNormalReturnOperations` exposes the following
premises as distinct fields:

| Running Python operation | Lean operation judgment | Additional premise / boundary |
|---|---|---|
| Parse loop; `Config(tuple(edges), tag)`; edge/tag guards; `tuple(graphs)`; `FractionCall` on an already decoded rational | `parsedCall : ParseRowsCall source parsed` | Assumes typed `WireRow` inputs and canonical graphs. It composes row-level `ConfigCall` and identity `FractionCall` judgments in input order. This bridge does not refine raw `Fraction(n,d)` or prove numerator/denominator decoding; those precede its typed boundary. |
| `joint(parsed, arity=2)`, exact rational addition/cancellation, ordered Config-pair dictionary keys, support sorting and `Joint(2, terms)` validation | `jointCall : JointCall normalizer parsed result` | The relation makes the actual result equal to the abstract `normalizer parsed`. This is an explicit open implementation premise: the Lean bridge does not yet derive it from the Python helper's dictionary/aggregation code. |
| `rows(value)`, `_row`, `_graph`, list comprehensions, exact numerator/denominator reads | `serializedCall : RowsWriteCall result encoded` | Models ordered row iteration, both coordinates and nullable tags. Stable helper bindings and no mutation are required. |
| Built-in equality of exact list/dict/int/string/null values | `builtinEquality : guardValue = decide (encoded = source)` | Requires exact built-in containers and values, unchanged bindings, no custom equality methods and no concurrent mutation. It does not state the lists are equal. |
| `if rows(value) != source['rows']: raise ...; return value` | `normalBranch : guardValue = true` | Records the selected normal control-flow branch. Combined with the comparator contract, Lean derives equality; equality is not directly supplied as a premise. |

All premises also require normal completion: allocations, iteration, exact
arithmetic, comparisons and sorting terminate without exception, resource
exhaustion, signal, process exit or external interruption. Rejected malformed
inputs and caught admission exceptions are outside this normal-return theorem.
The pinned bindings must remain stable throughout the call; monkeypatching,
rebinding and mutation are excluded.

## Derived result

The proof converts the operation judgments to #138's selected parser, Joint,
serializer and equality-guard call sequence. From `builtinEquality` and
`normalBranch`, it derives the modeled guard fact and builds
`ModeledNormalExecution`. The existing #135 theorem then yields the exact
typed rows. A changed serialized row list cannot satisfy the normal-branch
premises (`false_guard_cannot_return_normally`).

The code-selection check remains
`e7c_joint_admission_translation.py --check`; it pins selected AST sites but
does not establish any operation premise. Existing focused executable tests
exercise signed `Fraction(-2, 3)`, null versus empty tags, changed
coefficients, correlation, row order, duplicate/cancellation rejection and a
forged serializer binding. The forged binding is a counterexample to the
stable-binding premise, not a counterexample to the conditional theorem.

## Remaining links

The theorem is a conditional operation-to-trace proof, not a verified
CPython implementation refinement. In particular, deriving `jointCall` from
the actual `joint` helper and proving that Python's `Fraction`, dataclass,
container, sorting and serializer operations satisfy their contracts remain
open. Raw JSON validation and decoding to `WireRow` also remain outside the
theorem. The independent IR execution link under its separate `/0.5` and
`/0.6` package bounds, followed by stage two including its charged failed
second append, is subsequent work. EEC-Q and E7C calculus completion remain
open.
