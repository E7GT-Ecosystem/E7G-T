# CPython-to-modeled normal-return bridge

## Status and scope

This is a bounded, conditional bridge for the selected `admit` normal-return
path in `e7c_eecq_joint_restrict_b1.py`. It starts from an already decoded
`List WireRow` and ends at the #138 `ModeledNormalExecution` trace. It does not
interpret raw JSON, prove all CPython semantics, cover exception/resource
paths, or establish the independent IR or second-stage links.

The new Lean result is
`E7CJointAdmissionCPythonBridge.pinned_normal_return_yields_modeled_trace`.
Given operation-result equations and the pinned normal-return control-flow
fact, it constructs #138's modeled trace. The bridge derives the three #135
call judgments; those judgments are not fields or assumptions of its
operation record. Composing with
`pinned_normal_return_exact_rows` gives exact ordered typed rows, including
both correlated coordinates, tags and rational coefficients.

## Operation premises

The Lean structure `CPythonOperationRefinements` exposes operation outcomes
as distinct fields:

| Running Python operation | Lean operation-result premise | Derived call judgment / boundary |
|---|---|---|
| Parse loop; `Config(tuple(edges), tag)`; edge/tag guards; `tuple(graphs)`; `FractionCall` on an already decoded rational | `configLeftRefines`, `configRightRefines`, `fractionRefines`, `canonicalAccepted`, and ordered `parserIteration` result equation | From these and the definition of `parseRows`, Lean derives `ParseRowsCall source parsed`. Raw JSON integer decoding and CPython `Fraction(n,d)` remain outside the typed `WireRow` boundary. |
| `joint(parsed, arity=2)`, exact rational addition/cancellation, ordered Config-pair dictionary keys, support sorting and `Joint(2, terms)` validation | `jointOutputRefines : result = normalizer parsed` | Lean derives `JointCall normalizer parsed result`. The normalizer is still the #135 abstraction. Proving the Python helper's dictionary aggregation and sort implement this particular function remains an open implementation premise. |
| `rows(value)`, `_row`, `_graph`, list comprehensions, exact numerator/denominator reads | `rowsOutputRefines : encoded = serializeRows result` | Lean derives `RowsWriteCall result encoded`. This equation is still an operation adequacy premise; exact built-in values, stable bindings and no mutation are required. |
| Built-in equality of exact list/dict/int/string/null values | `builtinEqualityRefines : equalityResult = decide (encoded = source)` | Requires exact built-in containers and values, unchanged bindings, no custom equality methods and no concurrent mutation. It does not state the lists are equal. |
| `if rows(value) != source['rows']: raise ...; return value` | `normalReturnBranch : equalityResult = true` | Records the actual selected control-flow branch under the source-selection and stable-execution premises. The Lean theorem derives serialized equality from this and the comparator contract. |

All premises also require normal completion: allocations, iteration, exact
arithmetic, comparisons and sorting terminate without exception, resource
exhaustion, signal, process exit or external interruption. Rejected malformed
inputs and caught admission exceptions are outside this normal-return theorem.
The pinned bindings must remain stable throughout the call; monkeypatching,
rebinding and mutation are excluded.

## Derived result

The proof derives the parser call from its operation results and canonical
input, derives the Joint call from the aggregation result equation, derives the
serializer call from its output equation, and derives the modeled guard from
`builtinEqualityRefines` and `normalReturnBranch`. It then builds
`ModeledNormalExecution`. The existing #135 theorem then yields the exact
typed rows. A changed serialized row list cannot satisfy the normal-branch
premises (`different_rows_preclude_normal_return`).

The code-selection check remains
`e7c_joint_admission_translation.py --check`; it pins selected AST sites but
does not establish any operation premise. Existing focused executable tests
exercise signed `Fraction(-2, 3)`, null versus empty tags, changed
coefficients, correlation, row order, duplicate/cancellation rejection and a
forged serializer binding. The forged binding is a counterexample to the
stable-binding premise, not a counterexample to the conditional theorem.

## Remaining links

The theorem is a conditional operation-to-trace proof, not a verified
CPython implementation refinement. The operation record no longer assumes
#135's call judgments, but it does assume operation-result equations. In
particular, #143 leaves the exact `joint` aggregation equation and `rows`
serializer equation as helper adequacy premises. Its exact-head build passing
does not discharge those premises.

The follow-on `E7CJointAdmissionPythonOperations.lean` decomposes these two
equations into operation traces. For `joint`, it records ordered dictionary
lookup/add/set steps, Fraction addition and zero-test contracts, the filtered
support, the result of Python's identity-key sort, term materialisation and
binary `Joint` construction. Lean proves that a trace with those individual
outcomes refines the corresponding list-based `jointNormalizer`. For `rows`,
the trace records edge-list and tag writes plus the exact Fraction numerator
and denominator fields; Lean derives `RowsWriteCall` from their field-level
equations and the list-comprehension order. The composed theorem
`actual_helpers_yield_modeled_trace` therefore no longer assumes either
whole-result equation.

This remains conditional on explicit CPython primitive and helper-operation
premises, including key equality, rational operations, field reads, normal
completion and stable bindings. The list-backed dictionary model does not
model hash-table lookup; the unused hash premises have been removed. The
observed result of Python's `sorted` call and the constructor's copying of its
input terms remain explicit assumed observations. This increment does not
derive CPython's sorting or constructor behavior. The raw-row decoder now represents exact integer versus boolean
values, positive denominator and nonzero numerator checks, canonical graph
checks, and preservation of row order up to 64 rows. It still starts from a
typed row/graph shape; JSON parsing, exact dictionary key sets and malformed
array/object shapes have not been interpreted. Raw numerator/denominator JSON
equality with canonical output is also not yet composed with the typed-row
normal-return guard.

The independent IR execution link under its separate `/0.5` and `/0.6`
package bounds, followed by stage two including its charged failed second
append, remains subsequent work. EEC-Q and E7C calculus completion remain
open.
