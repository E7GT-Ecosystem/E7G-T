# Selected Joint source/IR implementation instances (review candidate)

Baseline: main `0e84e7b501076534fc42ff8dcccb58b1311cdee3`
(PR #110 merge). Edition: `E7C-EECQ-JOINT-TWO-STAGE/0.1-provisional`,
source v0.12.1/RGP2. Target: the selected finite binary correlated Joint
restriction followed by a restriction on its retained Joint.

This package strengthens the **actual-path instance** bridge after the
conditional Lean transition theorem. `certify_both` executes the first-party
Python source and independent IR paths with optional charge/append/terminal
probes, preserves the admitted source and entire IR package, both unmodified
results and transcripts, source digest, and exact observation. It invokes
the existing full source/IR replay and checks that both paths have identical
decoded observations and transition transcripts. Both are checked against
the separate staged exact-row rule before an instance certificate is returned.
The three-way portions retain graph identities and reduced signed rationals;
event metadata is checked before projection to the Lean model.

The transcript checker previously accepted an internally consistent lie at
one resource boundary: a first-stage run that stops after only one row could
claim the *entire* first-excluded portion, and a forged terminal could say
the second stage was reached. It now compares the whole observation to the
staged traversal, including stage completion and `secondStarted`. Regression
tests cover that forged completion, a false second start at zero fuel, the
failed second-attempt append, missing/altered terminal and row probes, and
paired source/IR instances for empty and nonempty correlated Joint inputs.

`E7CEECQTwoStageImplementationPath.lean` now proves a paired-path theorem:
**if** separate source and IR `Trace` certificates start from the same
encoded ordered rows, policies and budgets, then both full Lean observations
agree and the ledger is the exact wire-event prefix. This is a theorem about
the model under explicit premises, not a proof that Python emits those
certificates on all admitted inputs.

## Open correspondence and completion status

This result is **covered with an open link**, not complete. The Python
checker is executable and runs on given inputs; its own semantics are not
verified in Lean. Python interpreter behavior, exceptions, dynamic call
paths, JSON/IR parsing, child-result/retained-Joint correspondence and
sound translation of every actual emitted transcript into the inductive
Lean `Trace` are not formalized for all admitted inputs. The recorded source
and IR samples cannot discharge these universal premises, even if every CI
check passes. No new general EEC-Q coverage, profile promotion or product
migration follows.

Next: formalize the admitted implementation subset or verify a compiler-level
