# E7C/0.1 bounded dynamic and denotational semantics — WP3-S review candidate

Status: `wp3_specification_drafted_unimplemented`

Authority: WP2 accepted at PR #36 head `e0d73ed8…`, merged as `ed2a49de…`

Canonical baseline: E7G-T v0.12.1-experimental, `RGP/0.1`, revision RGP2

This document specifies operational outcomes, resource-bounded evaluation,
ordered runtime ledgers, model-relative denotation and observable behaviour for
the accepted E7C-B1 static fragment. It is a specification only. It does not
authorize or contain an evaluator, runtime, witness implementation, stable
schema, API, IR, profile adapter or canonical-kernel change.

## 1. Scope and semantic staging

WP3 is split into two separately reviewed stages:

1. **WP3-S** fixes the bounded semantic contract in this document.
2. **WP3-I** may implement a disposable evaluator only after WP3-S acceptance
   and the slice-specific witness trust boundary have been reviewed.

The term and type grammar is exactly the accepted WP2 B1 grammar. WP3-S adds no
constructor and does not reopen WP2 conversion. `Projection` remains distinct
from source-preserving `View`; no operational rule converts one to the other.

### 1.1 Outcome-normal executable boundary

`Outcome[A,xi]` is a computation-result type, not an implicitly unwrapable
value. B1 currently has no outcome eliminator. The WP3-S executable judgement
therefore applies only to **outcome-normal** terms: an `Outcome` may occur as
the outer result of `apply`, `restrict`, `reconstruct` or `classify`, but not as
the source type consumed by another primitive. Outcome-typed variables may be
inert data, but cannot be consumed without a future explicit eliminator.

The accepted WP2 prototype does not yet enforce this source-position
restriction. This is recorded as `WP3-GAP-001`. Before WP3-I, review must choose
one of two explicit paths: add the outcome-normal admission check as a bounded
static amendment, or specify and type an outcome eliminator. Implicit flattening
or host-language exception propagation is prohibited. Until that choice is
reviewed, evaluator implementation remains blocked.

## 2. Runtime objects and judgement

Let `rho` be a finite value environment matching `Gamma`, `I` a pinned B1
interpretation environment, and `beta` an explicit resource policy. The
candidate deterministic big-step judgement is:

```math
\Delta;\Gamma;\Phi;\rho;I \vdash_{\beta}
t \Downarrow (o,\lambda).
```

`o` is exactly one terminal outcome and `lambda` is one ordered ledger. Big-step
is selected because B1 contains only finite unary terms and no concurrency,
interleaving or observable intermediate state. The ledger retains observable
operation order. A later concurrent or noncommuting fragment must introduce a
labelled small-step relation instead of silently extending these rules.

Evaluation is defined only after WP2 admission and typing. Therefore
`invalid_input` and `type_error` remain checker diagnostics outside this
relation. They are not operational outcomes in B1.

## 3. Terminal outcomes

For an outcome-normal term whose static result type is plain `A`, success
carries a value of `A`. For a terminal computation typed `Outcome[A,xi]`, the
same terminal tag family is the meaning of that computation type; it is not
wrapped in a second outcome. Evaluation returns one member of the disjoint sum:

```text
success(v, optional_witness)       where v : A
domain_error(diagnostic)
unsupported(capability)
undetermined(obligation)
resource_limit(bound, progress)
```

Profile extensions may add tags only through the admitted, disjoint
`OutcomeExtensionEdition`. Empty, zero, no candidate, domain failure and
resource exhaustion remain distinct. `success(empty)` is permitted only when
the declared success carrier itself has an admitted empty value and exact
evaluation produced it.

WP3-S does not define witness contents. `optional_witness` is `none` until the
separate witness contract is reviewed; an implementation must not place an
unreviewed trace object there.

## 4. Resource policy and progress

`beta` is an immutable finite record with at least:

```text
step_bound
candidate_bound
ledger_entry_bound
policy_edition
```

Administrative validation of the external document remains the WP2 admission
budget and occurs before evaluation. Runtime resource accounting is separate.
`progress` records the completed semantic steps, completed candidate checks,
last canonical candidate key and incurred ledger prefix. It is diagnostic
progress, never a successful partial value.

Exhaustion returns `resource_limit(beta,progress)`. An unresolved mathematical
or external obligation returns `undetermined(obl)`. Absence of a required
declared capability returns `unsupported(cap)`. None may be rewritten as an
empty success or a domain error.

## 5. Ordered ledger

The runtime ledger is a finite sequence:

```text
LedgerEntry = (ordinal, static_atom, detail)
lambda      = [entry_0, ..., entry_n]
```

`static_atom` is exactly one atom admitted by the WP2 effect row. `detail` is a
canonical operational record that may refine, but never change, that atom's
dimension or declaration identity. The erasure used for correspondence is:

```math
\mathsf{atoms}(\lambda)=
\{e.static\_atom \mid e \in \lambda\}.
```

Sequential composition is stable concatenation, not set union:

```math
\lambda_1 \mathbin{\mathord{+\!+}} \lambda_2.
```

For every terminal tag, including non-success:

```math
\mathsf{atoms}(\lambda) \subseteq \varepsilon
```

whenever WP2 derives `t:A ▹ epsilon`. A failing outer operation retains the
complete ledger prefix incurred by its argument. It then appends only entries
for checks or effects actually incurred before the failure. It never erases
loss, evidence, alternatives or resource reliance.

Evaluator-control counters in `progress` are not automatically semantic
`resources` atoms. A semantic resource entry is emitted only when authorized
by the term's WP2 effect row, notably reconstruction. This prevents evaluator
overhead from violating the accepted static bound.

## 6. Evaluation order and propagation

All compound B1 terms evaluate their sole argument first. If the argument
returns non-success, the outer term propagates that outcome and ledger without
attempting its declaration. Declaration identity and edition resolution is
static and has no runtime effect.

After a successful argument, the declared operation runs deterministically
under `I` and `beta`. Canonical ordering is required whenever a declaration
examines a finite family, carrier or candidate set. Host-language hash or map
iteration order is never semantic.

## 7. Operational rules

The rules below are specification rules. Side conditions such as
`I(f)(v)=...` refer to the pinned interpretation environment, not arbitrary
host-language callbacks.

### Variable

```math
\frac{\rho(x)=v}
 {\Delta;\Gamma;\Phi;\rho;I \vdash_{\beta}
  x \Downarrow (success(v,none),[])}
```

The judgement has no rule for a missing or ill-typed binding because admission
of `rho:Gamma` is a premise.

### Map application

Evaluate the argument first. Every attempted map emits its WP2 `evidence` atom
with detail identifying the declaration, edition, domain policy, failure family
and outcome extension.

- `total`: `I(f)` must return one value of the target carrier.
- `strict`: if the operand is outside the declared domain, return
  `domain_error`; otherwise apply `I(f)` to the whole operand.
- `filtering`: `I(f)` must explicitly return a typed target value plus retained
  and excluded alternatives. If no admitted target value exists, return
  `domain_error`; do not manufacture an empty target.

Strict and filtering attempts append their structured `partiality` atom.
Filtering detail records retained and excluded alternatives in canonical order.
An unavailable interpretation is `unsupported`, while an unresolved domain
obligation is `undetermined`.

### View or projection

After argument success, a `source_preserving` declaration returns a value of
`View[A,V,iota,q]` containing the representation, policy identity and admitted
source-return token. It emits `inquiry` and `alternatives(exact_source_return)`.

A `projection` declaration returns
`Projection[A,V,iota,Q,q_l]`. It emits `inquiry`, its structured `loss` atom and
the declared non-exact reconstruction obligation. Ledger detail records the
preserved and excluded observation identifiers and quotient relation. It does
not retain or reconstruct a hidden source by implication.

### Restriction

`I(p)` deterministically partitions the admitted finite input family into
retained and excluded subfamilies in canonical order. The successful value is
the declared output family. Its `alternatives(p)` ledger detail records both
subfamily identities. Failure or exhaustion cannot silently return the
retained prefix.

### Exact reconstruction

Reconstruction accepts only the exact named source-preserving
`View[A,V,iota,q]` admitted by WP2. Let the declaration provide a finite carrier
`C_A` and view comparison under `q`. Candidates are tested in canonical order:

```math
F_{q}(y)=\{a\in C_A \mid view_q(a)=y\}.
```

Success is permitted only after all of `C_A` has been checked and returns the
canonical exact fibre `F_q(y)`. Every reported candidate must map back to `y`.
If enumeration stops early, return `resource_limit` with progress. If carrier
finiteness, equality or an admitted constraint remains unresolved, return
`undetermined`. If enumeration capability is absent, return `unsupported`.
No rule returns a successful incomplete subset.

The ledger appends `resources(beta)` and `alternatives(r)` only as their checks
or reliance occur. Projection values have no exact-reconstruction rule.

### Classification

`I(kappa)` classifies every element of the exact input fibre and forms the
canonical partition induced by equal criterion results. It emits
`inquiry(kappa)`. Classification does not collapse the fibre to one
representative and does not assert representative-independent phase descent.
An unresolved criterion obligation yields `undetermined`.

## 8. B1 interpretation models

A B1 model `M` supplies:

- a set `[[Base[name]]]M` for each base carrier;
- admitted sets for `Entity` and finite `Config` signatures;
- structural interpretations of `Family`, `View`, `Projection`, `Fibre`,
  `Partition` and `Outcome` preserving every nominal index;
- a deterministic interpretation for each map, view, restriction,
  reconstruction and criterion declaration;
- canonical equality and ordering only where required by an admitted
  declaration;
- capability and obligation interpretations sufficient to distinguish
  `unsupported` from `undetermined`.

`[[Outcome[A,xi]]]M` is the terminal-computation interpretation given by the
disjoint tagged sum above, not a freely nested value carrier in WP3-S.
`[[View[A,V,iota,q]]]M` includes
the representation and governed source-return token. A projection denotes the
declared quotient observation and does not denote its source fibre. The fibre
denotation is the exact preimage set under the pinned view declaration and
finite carrier. A partition denotes the full family of criterion-equivalence
cells, not a chosen representative.

Plain terms and terminal computations denote deterministic resource-indexed
functions, with the codomain interpreted according to the outcome-normal
distinction:

```math
[[t]]_{M,\beta} : [[\Gamma]]_M
\longrightarrow Terminal([[A]]_M) \times Ledger_M.
```

Composition is outcome short-circuiting plus ordered ledger concatenation. This
is a writer-and-terminal-outcome structure for B1 only; WP3-S does not claim a
universal semantic category for future E7C fragments.

## 9. Operational–denotational correspondence

The intended adequacy obligation is:

```math
\Delta;\Gamma;\Phi;\rho;I_M \vdash_{\beta} t
\Downarrow(o,\lambda)
\quad\Longrightarrow\quad
[[t]]_{M,\beta}(\rho)=(o,\lambda).
```

The converse is required for the deterministic B1 fragment once an evaluator
exists. Both directions are `statement_drafted`; neither is a theorem or test
result. Proof belongs to WP4.

| Constructor | Operational meaning | Denotational meaning | WP3-S status |
|---|---|---|---|
| `var` | environment lookup | projection from `[[Gamma]]` | specified |
| `apply` | policy-sensitive declared map | total/partial deterministic map into tagged outcome | specified |
| `view` (source-preserving) | governed representation with source return | indexed view carrier | specified |
| `view` (projection) | lossy quotient observation | quotient-indexed projection carrier | specified |
| `restrict` | canonical retained/excluded split | finite-family partition by policy | specified |
| `reconstruct` | exhaustive bounded fibre computation | exact finite preimage | specified |
| `classify` | canonical criterion partition | quotient into criterion cells | specified |

No row is implemented by this package.

## 10. Observable behaviour

The full B1 observation is:

```text
(terminal tag,
 canonical success value if any,
 ordered ledger,
 resource bound and progress if any,
 unresolved obligation or missing capability if any,
 optional reviewed witness if any)
```

Two evaluations are B1-observationally equivalent only when this tuple is
equal under a named observation policy. A policy may intentionally hide a
component, but must name that quotient. Same success value with different loss,
evidence, alternatives, order, failure tag or resource progress is not
equivalent by default.

Denotational equality remains model-relative. Observational or phase equality
never enters WP2 conversion.

## 11. Required counterexamples

Any WP3-I evaluator must include at least these cases:

1. strict partial-map domain failure is not zero or empty success;
2. filtering records both retained and excluded alternatives;
3. lossy projection cannot enter exact reconstruction;
4. reconstruction exhaustion returns `resource_limit`, never partial success;
5. unresolved fibre equality returns `undetermined`;
6. non-success preserves the incurred ledger prefix;
7. identical success values with different ledgers remain observably distinct;
8. classification does not infer representative-independent phase descent.

## 12. Review gate and non-claims

WP3-S may pass only if review confirms:

- every accepted WP2 constructor has one deterministic operational meaning and
  one model-relative denotational meaning;
- terminal tags are disjoint and admission diagnostics remain pre-operational;
- `WP3-GAP-001` is resolved through a reviewed outcome-normal static amendment
  or an explicit typed eliminator before evaluator implementation;
- every non-success retains its incurred ledger prefix;
- ledger erasure is bounded by the accepted WP2 effect row;
- evaluation order and canonical finite enumeration are explicit;
- reconstruction success means exact completed fibre computation;
- observable behaviour includes outcome, ledger and resource information;
- no evaluator, witness, IR, runtime, API, adapter or canonical promotion is
  smuggled into the specification.

Acceptance authorizes only a separately scoped witness-contract review and
then a disposable WP3-I evaluator branch. It does not establish determinism,
preservation, adequacy, progress, reconstruction completeness, external truth,
scalability, independent reproduction or product value.
