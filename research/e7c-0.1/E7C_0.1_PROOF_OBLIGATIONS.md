# E7C/0.1 WP4-S initial metatheory

Status: `wp4_s_revision_addressed_pending_rereview`

Baseline: PR #39 merge `9f997801eba3ff526f7caa83b6a4a1980a713bcb`

Scope: the finite, binder-free E7C-B1 fragment fixed by the accepted WP2 and
WP3-S specifications, together with the disposable WP3-I implementation. This
is a theorem-statement and proof-sketch package. It is not machine checked and
does not establish conformance, soundness or correctness of the implementation.

## 1. Status vocabulary and hypothesis catalogue

The only proof statuses are `stated`, `proof_sketch`, `proved_on_paper`,
`mechanised`, `bounded_exhaustive_check`, `counterexample_found`, and
`withdrawn`. Bounded tests are supplementary evidence and never upgrade a
theorem to `proved_on_paper` or `mechanised`.

The following labels apply only where listed under an individual theorem:

- `J1`: the candidate is a finite acyclic value in the canonical JSON data
  universe; it need not already be admitted or well typed;
- `A1`: the complete evaluation document has passed canonical-JSON,
  closed-shape, WP2 static, runtime-carrier, interpretation and edition
  admission;
- `A2`: atomic carriers and interpretation tables are finite, canonical,
  duplicate-free and complete under the pinned interpretation edition;
- `A3`: the resource policy has the supported edition and finite non-negative
  integer bounds, excluding Boolean values;
- `A4`: external assumptions have their exact closed shape and typed canonical
  JSON fields;
- `S1`: `Gamma |- t : T ! epsilon` is a derivable B1 static judgement;
- `D1`: evaluation uses the formal deterministic WP3-S relation, not merely a
  Python implementation with the same field names;
- `M1`: a pinned B1 model interprets every referenced carrier and declaration;
- `C1`: canonical encoding and SHA-256 behave as specified; collision
  resistance is an explicit cryptographic assumption, not a theorem here;
- `N1`: no host callback, network input or concurrent mutation participates in
  checking or evaluation.

## 2. Static obligations

### E7C-T001 — Formation and typechecking decidability

- Applicable hypotheses: `J1`; the input obeys the published finite depth and
  node limits. `A1` is deliberately **not** assumed.
- Exact statement: admission and typechecking terminate and return exactly one
  controlled diagnostic or one unique B1 type/effect judgement.
- Status: `proof_sketch`.
- Argument: structural parsing descends through a bounded finite JSON tree.
  Each term has at most one strict subterm. Closed record checks, nominal
  lookups, structural equality and finite-set unions terminate. Rule heads are
  disjoint by tag, and each side condition has one result.
- Counterexample search: cyclic and non-JSON host values are outside `J1` and
  handled by T009B. Depth, unknown-tag, extra-field and terminal-nesting
  fixtures return controlled diagnostics; no counterexample was found within
  the stated domain.
- Mechanisation disposition: formalize finite syntax and the checker after the
  common proof spike; prove termination and result uniqueness.

### E7C-T002 — Exchange for the reusable variable context

- Applicable hypotheses: `S1`; context bindings have distinct exact names.
- Exact statement: for every permutation `pi` of `Gamma`,
  `Gamma |- t:T!epsilon` iff `pi(Gamma) |- t:T!epsilon`.
- Status: `proof_sketch`.
- Argument: lookup is by exact identifier rather than position. Induction on
  the unary term spine reduces the claim to variable lookup; effect output is
  canonically sorted.
- Counterexample search: duplicate identifiers are not admitted, and no rule
  observes serialization order. No counterexample found under the hypotheses.
- Mechanisation disposition: include after the reusable finite-context
  representation is fixed; not required for the minimal common spike.

### E7C-T003 — Weakening by a fresh reusable binding

- Applicable hypotheses: `S1`; `y` is fresh; `B` is an admitted terminal-normal
  B1 type; the context is reusable, not linear or affine.
- Exact statement: if `Gamma |- t:T!epsilon`, then
  `Gamma,y:B |- t:T!epsilon`.
- Status: `proof_sketch`.
- Argument: `t` has no occurrence of fresh `y`; existing exact lookups are
  unchanged. Induction reapplies each constructor rule.
- Counterexample search: the result fails for hypothetical consumable contexts,
  so the theorem is limited to B1 and does not close ADR-001.
- Mechanisation disposition: prove after the common spike once context extension
  is represented.

### E7C-T004 — Substitution for the binder-free unary fragment

- Applicable hypotheses: `Gamma,x:A |- t:B!epsilon_t` and
  `Gamma |- s:A!epsilon_s`; B1 has no binders or outcome eliminator.
- Exact statement, free case: if `x in FV(t)`, then
  `Gamma |- t[s/x]:B!(epsilon_t union epsilon_s)`.
- Exact statement, absent case: if `x notin FV(t)`, then
  `t[s/x]=t` and `Gamma |- t:B!epsilon_t`; `epsilon_s` is not added.
- Status: `proof_sketch`.
- Argument: a B1 term is a unary spine and has at most one leaf variable
  occurrence. There is no capture or duplication. Induction replaces the
  variable premise in the free case and leaves the derivation unchanged in the
  absent case. An outcome-typed `x` can occur only as the entire term.
- Counterexample search: the former informal formula blurred the absent case;
  the split statements remove that overreach. No counterexample found for the
  revised statement.
- Mechanisation disposition: mandatory in the common Lean/Rocq/Isabelle spike.

### E7C-T005 — Structural conversion soundness

- Applicable hypotheses: `M1`; `A` and `B` are admitted B1 type trees and
  `A defeq_B1 B`.
- Exact statement: `interpret_M(A) = interpret_M(B)` for every pinned admitted
  model whose type interpretation is structural on B1 constructors.
- Status: `proof_sketch`.
- Argument: B1 definitional equality is equality of parsed canonical type
  trees; structural recursion maps equal constructors and arguments equally.
- Counterexample search: the converse fails in models identifying distinct
  carriers, so no converse is claimed.
- Mechanisation disposition: prove after a minimal model interpretation exists;
  outside the first operational spike.

## 3. Dynamic and API obligations

### E7C-T006 — Deterministic formal evaluation

- Applicable hypotheses: `A1`, `A2`, `A3`, `D1`, `N1`.
- Exact statement: a closed admitted term and initial resource state have at
  most one terminal outcome, ordered ledger and progress record under WP3-S.
- Status: `proof_sketch`.
- Argument: induction on the unary term spine. Step charges, guards and
  canonical table lookups are functional. Candidate order is unique, and rule
  branches have disjoint side conditions.
- Counterexample search: arbitrary table order, duplicate inputs and missing
  rows would break the argument but are excluded by `A2`; regressions cover
  those admission boundaries.
- Mechanisation disposition: planned after the common spike fixes the formal
  operational-relation representation.

### E7C-T007 — Successful type preservation

- Applicable hypotheses: `A1`, `A2`, `S1`, `D1`.
- Exact statement: if evaluation returns `success(v,w)`, then `v` inhabits `T`
  when `T` is plain, and inhabits `A` when `T=Outcome[A,xi]`.
- Status: `proof_sketch`.
- Argument: induction on evaluation. Bindings and table outputs are checked
  against carriers; restriction and reconstruction return carrier members;
  classification partitions fibre members. Outcome variables return validated
  terminal bindings without nesting.
- Counterexample search: projection-as-view and out-of-carrier rebound witnesses
  previously violated the implementation boundary and are now rejected. No
  counterexample found under the revised hypotheses.
- Mechanisation disposition: mandatory successful-preservation theorem in the
  common proof spike; later extend to every constructor.

### E7C-T008 — Effect preservation and ordered-ledger soundness

- Applicable hypotheses: `A1`, `S1`, `D1`.
- Exact statement: for every terminal outcome and ledger `lambda`,
  `atoms(lambda) subseteq epsilon`; propagated non-success retains the complete
  incurred child prefix in order.
- Status: `proof_sketch`.
- Argument: induction on evaluation. Variables emit no entries. Each
  constructor appends only atoms present in its WP2 rule. Every early exit
  returns the current stable prefix without deletion.
- Counterexample search: zero ledger bounds, guard failures, strict-domain
  failure and propagation are covered. Equal atom sets do not imply equal
  ledger order.
- Mechanisation disposition: formalize after determinism; ordered sequences and
  set erasure must remain distinct.

### E7C-T009 — Declared progress and API totality

- Applicable hypotheses for T009A: `A1`, `A2`, `A3`, `D1`.
- Exact statement T009A: every closed admitted term returns exactly one declared
  terminal outcome and finite progress record under WP3-S; it does not enter an
  undefined semantic state.
- Status T009A: `proof_sketch`.
- Argument T009A: the finite term spine, bounded charges and finite canonical
  carriers give a lexicographic termination measure. Exhaustion returns
  `resource_limit`; admission excludes missing semantic material.
- Applicable hypotheses for T009B: an arbitrary host input is presented to the
  evaluator API.
- Exact statement T009B: the evaluator rejects before evaluation with
  `EvaluationInputError` or, after complete admission, returns the T009A result;
  non-JSON values, non-finite numbers, invalid external assumptions, Boolean
  bounds and unknown policy editions do not escape as host exceptions.
- Status T009B: `proof_sketch` plus `bounded_exhaustive_check` for named attacks.
- Counterexample search: bytes in policy/external fields and NaN previously
  escaped as host exceptions. The boundary now validates canonical JSON first,
  and the theorem is split rather than hiding the counterexample.
- Mechanisation disposition: mechanize T009A with the formal relation. T009B is
  an implementation/API property maintained by negative tests and code review.

### E7C-T010 — Reconstruction soundness and bounded completeness

- Applicable hypotheses: `A1`, `A2`, `A3`, `D1`; reconstruction and exact-view
  obligations are resolved.
- Exact statement: successful exact reconstruction returns precisely
  `{a in Carrier(A) | view_q(a)=v}` in canonical order; interruption returns
  `resource_limit`, never a partial success.
- Status: `proof_sketch`.
- Argument: the reconstruction carrier exactly enumerates the source carrier
  without duplicates and the view table is total. Every member is checked once
  and included iff target equality holds. Success follows loop completion.
- Counterexample search: missing comparisons and incomplete carriers once
  admitted false complete fibres; closed admission now rejects them.
- Mechanisation disposition: formalize soundness and completeness as separate
  finite-carrier lemmas.

### E7C-T011 — Replay equality versus semantic soundness

- Applicable hypotheses for T011A: a canonical witness passes exact envelope,
  judgement-class, claim-class, rule-pin, resource-edition, closed-graph,
  static and runtime admission; `C1` applies to identity binding.
- Exact statement T011A: if the implementation checker accepts, its independent
  `ReplayMachine` result equals the claimed outcome, ledger, progress, bottom-up
  nodes and root identity.
- Status T011A: `proof_sketch` plus bounded adversarial checks.
- Argument T011A: acceptance follows only after exact comparisons with the
  independently recomputed implementation result. This is implementation
  replay equality, not semantic correctness.
- Counterexample search T011A: rebound changes to `judgement_class` and arbitrary
  resource-policy editions were accepted at the reviewed head. Both are now
  pinned and tested, including wrong JSON types.
- Mechanisation disposition T011A: primarily an implementation-refinement
  property; formalize the witness predicate only after schema stabilization.
- Applicable hypotheses for T011B: T011A and E7C-T017.
- Exact statement T011B: checker acceptance implies existence of the claimed
  formal WP3-S derivation under the pinned editions.
- Status T011B: `stated`.
- Counterexample search T011B: equality with `ReplayMachine` alone cannot prove
  adequacy; no semantic-soundness conclusion is currently licensed.
- Mechanisation disposition T011B: prove only after E7C-T017. Source truth and
  domain authority remain outside the conclusion.

## 4. Precisely stated later obligations

### E7C-T012 — Canonicalisation soundness

- Applicable hypotheses: `M1`; a future `can_A` is total on admitted carrier
  `A`.
- Exact statement: for every `v:A`,
  `interpret_M(can_A(v)) = interpret_M(v)`, and `can_A` is idempotent.
- Status: `stated`.
- Counterexample search: no general `can_A` relation exists; host sorting is not
  semantic evidence. Search has not advanced beyond identity fixtures.
- Mechanisation disposition: define canonicalisation per carrier before proof.

### E7C-T013 — Composition soundness

- Applicable hypotheses: future typed `g o f`; resolved domain conditions;
  `M1`; compatible outcome extensions and effect composition.
- Exact statement: whenever `g(f(v))` is admitted,
  `interpret_M(g o f)(v)=interpret_M(g)(interpret_M(f)(v))`, with identical
  declared failures and ordered incurred effects.
- Status: `stated`.
- Counterexample search: B1 has no composition constructor; equal final values
  with different failures or histories refute weaker formulations.
- Mechanisation disposition: defer until reviewed composition rules exist.

### E7C-T014 — Quotient descent

- Applicable hypotheses: phase equivalence `~`, partial `f`, declared quotient.
- Exact statement: `f` descends iff its domain is saturated under `~` and
  results are congruent: admitted `x~y` are both outside the domain or both
  inside with `f(x)~f(y)`.
- Status: `stated`.
- Counterexample search: the retained phase-descent example shows result
  congruence alone is insufficient without domain saturation.
- Mechanisation disposition: formalize with the WP5 phase adapter.

### E7C-T015 — Adapter conservativity or relative faithfulness

- Applicable hypotheses: pinned source `S`, E7C fragment `C`, translation `F`,
  and named source/target observation relations.
- Exact statement: a faithful embedding preserves typing, admission, successful
  values and failures and reflects selected source equality/observations. A
  lossy adapter proves this only modulo its named quotient.
- Status: `stated`.
- Counterexample search: agreement of bounded outcome tags alone erases source
  distinctions and is insufficient.
- Mechanisation disposition: one proof module per WP5 adapter and edition.

### E7C-T016 — Lowering adequacy

- Applicable hypotheses: future versioned IR, typed lowering `L`, source/IR
  evaluators and selected source fragment.
- Exact statement: for each admitted `t`, source evaluation and IR evaluation
  of `L(t)` have equal observable outcomes, ordered ledgers and declared
  failures under the pinned observation policy.
- Status: `stated`.
- Counterexample search: no IR exists; equal success payload alone is retained
  as an inadequate criterion.
- Mechanisation disposition: WP6 differential proof and executable fixtures.

### E7C-T017 — ReplayMachine adequacy to WP3-S

- Applicable hypotheses: `A1`–`A4`, `D1`, `N1`; a formal encoding relation
  connects Python data to WP3-S terms, values, interpretations and resources.
- Exact statement: if `ReplayMachine.execute(t)` returns implementation tuple
  `(o,lambda,progress,derivation)`, the corresponding formal WP3-S judgement
  derives `(o,lambda)` with the same progress and rule tree; every formal B1
  derivation in the executable fragment is reproduced by `ReplayMachine`.
- Status: `stated`.
- Counterexample search: matching evaluator and checker implementations cannot
  establish this theorem. Prior admission/resource bugs demonstrate why an
  explicit refinement relation is required.
- Mechanisation disposition: define the encoding/refinement relation, prove
  soundness, then bounded completeness. T011B remains blocked until then.

## 5. Evidence boundary

The WP4 and WP3-I suites provide only `bounded_exhaustive_check` evidence over
named finite fixtures. No theorem here is `proved_on_paper` or `mechanised`.
Implementation replay equality (T011A) must never be cited as formal WP3-S
soundness (T011B).
