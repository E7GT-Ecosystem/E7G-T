## Disposition and boundary

**Proposed disposition: `partial_translation`.** The target is a provisional
`EEC-Q-FG3-B1/0.1` profile module associated with E7C, implemented in
`adapters/eec_q_fg3_b1.py`. It is not a constructor in the accepted E7C-B1
core, a stable E7C IR, a public schema or an accepted adapter fidelity result.
The existing WP2/WP3-B1 fragment has no executable `State[Σ]` carrier or
rational linear operations. This module does not pretend that a `Family`, a
finite map table or a `Config` alone is an EEC-Q formal state.

**Admitted source fragment:** finite FG3 graph rows with exact rational
coefficients; canonical graph identity including edges and semantic tag;
linear addition and scaling; registered total graph rules (`add`, `remove`,
`forget_tag`, `empty`); and strict `require_absent`. The source graph/row record
is explicit finite data. A source `Graph` can be exported as `{edges,tag}`;
a `State` as ordered `{config,coefficient}` rows. A coefficient is an integer
numerator and positive integer denominator. The translator validates every
supplied graph and coefficient before collecting equal configurations, even
if the coefficient is zero or the row would later cancel.

| Source | Target | Preserved observable | Exclusion |
|---|---|---|---|
| `Graph(edges,tag)` | `Config(edges,tag)` | FG3 exact identity | no arbitrary E7G-T configurations |
| `State` finite rational terms | `State` canonical terms | signed exact coefficients, finite support, zero distinct from the empty-graph basis | no joint/dependent or quoted state |
| `state`, `add`, `scale` | `translate_rows`, `add`, `scale` | admission before cancellation, exact collection | no host float coercion |
| FG3 total graph rule | `Rule` with `domain_policy=total`, `push` | output collisions and cancellation | no arbitrary rule grammar |
| `require_absent` | strict `Rule`, `push` | whole success or `domain_error`; zero support succeeds | no filtering fallback |
| FG3 `InvalidInput` | `AdmissionError` | pre-evaluation invalid input distinct from zero | diagnostic strings and general resource accounting not preserved |

Target success and domain failure are tagged `Outcome` values. The source FG3
example raises `DomainError`; the differential checker compares the tags while
leaving the source's host-language API untouched. No internal evaluator
exception is offered as a target result. No semantic metadata is dropped
within the selected graph fragment. Order of input rows is erased **only after**
individual admission, as licensed by canonical formal-state collection.
Signed coefficients are neither probabilities nor REC evidence weights.

## Fidelity and proof obligations

On admitted graph rows, the proposed relation equates exact configuration
identity and rational coefficients after canonical collection. Graph identity
is reflected by edges and tag; finite formal-state equality is reflected by
the tuple of canonical graph keys and reduced rational pairs. Under a
registered rule, compare exact success states or the strict domain-failure
tag. The fixture suite exercises this relation against the pinned FG3 model.
It is *first-party differential evidence*, not a proof of fidelity for all
finite states or a verified implementation of the E7C source semantics.

Deferred obligations: formal module typing/effects, model-relative denotation,
total-vs-strict failure theorem, source-to-target preservation and reflection
proofs, finite-resource outcomes, executable witness/replay, independent
implementation, and a stable external syntax. Required later EEC-Q scope not
translated here includes joint dependence, independent gluing, variable
connections, restriction with retained/excluded states, source-preserving
views, identification/projection, quotes, rank, history and arbitrary declared
signatures. Requests for these forms must be rejected by this adapter boundary,
not silently mapped to a graph rule. No quotient or representational loss is
licensed for the admitted fragment; the broader source is outside the domain.

## Differential cases and acceptance gate

Run `python -m unittest discover -s research/e7c-0.1/adapters -p 'test_*.py' -v`.
The 11 named cases in `adapters/fixtures/fg3_graph_differential.json` include:
exact zero versus empty-graph basis, negative cancellation, fraction collection,
total-map collision, tag identification, strict failure, strict zero support,
invalid opposite rows, invalid zero row and float rejection. Additional cases
compare signed scaling and addition to FG3. The target implementation does not
call the FG3 evaluator; only the differential test imports the source model.

WP5 EEC-Q acceptance requires an exact-head review of the source/target pins,
admission boundary, translation, differential cases and named exclusions. Even
acceptance would cover only this stated graph fragment. The rest of WP5 and
full E7C/0.1 foundation remain open.

Compatibility: no canonical kernel, existing profile meaning, IDs, data,
schemas, APIs or consumer is changed. No product migration is proposed.
