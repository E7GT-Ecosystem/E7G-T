# Selected transition-site coverage audit (merged provisional)

Accepted bounded head: PR #107 `3e45f3ff26e67d6f8059f18328dd18e2f465754e`,
merged as `ada63dff19e284af08d21f51d04fc687d07300d5`.
Baseline was main `1bd08763545a081f2604cb862abf38fe35a2a9ec` (merged
provisional #106). The accepted conditional Lean theorem requires a complete
certificate of charge, append and terminal behavior from each actual path.

`e7c_eecq_two_stage_transition_site_audit.py` parses the four selected
Python source/IR functions and checks that every direct `steps += 1` is
followed immediately by an opt-in `emit("charge")`. At the second attempt,
`second_started = True` must intervene before that emit. Every direct
`ledger.append` must be followed immediately by `emit("append")`; other
recognized ledger mutation methods and alternative arithmetic assignments
to `steps` fail the audit. It verifies each outer path forwards the sink to
its first-stage child, and checks the expected two charge and two append
sites per function. Adversarial tests delete or reorder probes and child
forwarding; the audit rejects them.

This protects a precise **syntactic** property of the pinned four source
files. PR #106's runtime transcript checker supplies separate finite
execution evidence. Neither check proves Python evaluation semantics,
completeness against dynamic mutation, JSON admission, child-result
correctness, or that the emitted transitions instantiate Lean `Trace` on all
admitted inputs. The conditional refinement gate remains open. No published
source, profile edition or product API changes.
