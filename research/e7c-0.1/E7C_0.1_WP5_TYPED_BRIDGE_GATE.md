## Plain-language build position

The repository now contains working, independently coded FG3 examples for
exact formal graph combinations, strict rules, correlated choices, gluing,
view versus identification, whole-state quotation and finite candidate
fibres. The new `adapters/eec_q_fg3_typed_bridge.py` lets selected examples
be composed through one edition-pinned type/effect check and one tagged
outcome path. It rejects operations on the wrong kind of value before running
them; a phase result cannot be passed to exact source return, and a quote
cannot silently receive a graph rule.

**This is still a provisional profile module.** The accepted E7C-B1 static
grammar has no `State[Σ]` or `Joint[Σ,…]` types, and its evaluator/checker
cannot execute/replay these new values. The bridge does not revise that core
or make a general E7C program, compiler, proof or product. It supplies a
small executable integration target for the next formal extension.

## Module declaration and controls

The nominal module edition and the two immutable source blob pins are in the
code. Imported implementations are the already integrated provisional FG3
graph, joint, assembly, phase, retained-view and quote modules from the same
repository head; runtime import hashes and independent source reproduction
are not asserted. Exported sorts are graph state, **untagged** graph state,
binary/ternary graph joint, assembly state, phase state, retained source view
and rank-one whole quote. The type checker admits a closed action table:

| Action | Input → output | Declared effect beyond a module step |
|---|---|---|
| add or require `AB` absent | graph state → graph state | strict partiality for require |
| pair or wire-choice join | binary/ternary graph joint → assembly state | strict partiality for wire-choice |
| identify phase | untagged graph state → phase state | loss of exact graph identity |
| project view; source return | untagged graph state → view → untagged graph state | pinned inquiry for view |
| pack; execute inside | graph state → quote → quote | strict partiality for inside-require |

There are two terminal tags for these actions: `success` and `domain_error`.
Admission/type errors are pre-evaluation failures. The incurred effect ledger
records a module-step charge and any actual strict-domain failure, loss or
inquiry event. Each ledger event belongs to the checked static effect bound.
This is a **one-step accounting model**; it is not a complete resource budget,
an external witness, a replay checker or a proof of the WP3 correspondence.
The retained view supplies exact source return; `identify_phase` is an
explicit many-to-one map under the pinned untagged edge-count quotient and
does not support exact source return. No effect silently restores erased
identity. The bridge itself does not expose finite-fibre reconstruction;
that remains a separately typed, candidate-relative provisional operation.

## Gate decision and order of work

The six new test methods cover static type mismatch before execution,
retained-source return versus lossy identification, no implicit quote entry,
strict whole-result failure with incurred partiality, and edition rejection.
An exact-head review can accept **this finite composition target** without
declaring EEC-Q, WP5 or E7C/0.1 complete. Remaining blockers for the actual
calculus are:

1. Specify and admit versioned `State[Σ]`, `Joint[Σ₁,…]`, rank-one quote,
   exact rational coefficient and profile-module typing/effect rules in an
   E7C static-semantics successor. Preserve existing B1 programs.
2. Give every admitted operation a model-relative denotation and operational
   rule, then implement resource/ledger semantics and a separately replaying
   checker for the chosen fragment. Prove or state bounded preservation,
   reflection and no-partial-success obligations.
3. Perform exact-head review of that successor and its adapters before a
   stable IR/compiler (WP6), general witness (WP7), or product pilot (WP8).
   WPC follows EEC-Q in the WP5 adapter order; its adapter must retain native
   whole/portion identity rather than borrow FG3 graph semantics.

No canonical revision, source-profile replacement, migration of IDs/data/
schemas/APIs, or consumer adoption is proposed here. Passing first-party
tests does not establish independent correctness or external benefit.
