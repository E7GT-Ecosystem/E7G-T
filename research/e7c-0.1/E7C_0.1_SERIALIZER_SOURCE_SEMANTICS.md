## Source contract and result

`e7c_joint_serializer_source.py` translates the complete selected `_graph`,
`_row` and `rows` return expressions into `E7CJointSerializerSourceGenerated`.
It checks their signatures, sole return bodies and the exact native `Joint`
and binary-arity guard before translating. The existing complete helper AST
pins are checked too. The grammar includes lexical variable indices,
attribute reads, ordered dictionary/list construction, helper calls and
single-generator comprehensions with one-name or two-name binding. Dictionary
literals must have distinct string keys. Changes
outside that grammar are rejected. Helper bindings remain explicit.

`E7CJointSerializerSourceSyntax.eval` gives that grammar an executable
mathematical semantics. It is independent of `encodeRawRows`. The host value
carrier has typed graph, fraction and Joint references, plus sequences and
raw data. These are mathematical representations; their existence does not
establish actual Python objects or their constructor invariants.
`AttributeContracts` specifies only native edges/tag,
numerator/denominator and Joint terms/arity reads. It does not assume a
serializer output equation, helper result, completed serializer trace or
successful equality guard.

Lean proves for every finite typed row list that executing the generated
binary serializer produces `encodeRawRows`. This includes list order, both
correlated graph coordinates, ordered edge lists, null versus string tags,
and the returned rational's exact numerator and denominator. The theorem
derives `RowsStatementTrace`, fuel safety and recursive unique keys from the
source interpreter result. `source_serializer_guard_recursive_equality`
supplies that derived trace to #157's guard theorem, while retaining its
separate admission, Joint and final-comparison premises.

The interpreter's fuel 16 bounds expression nesting in this selected
grammar. The all-list success theorem proves it sufficient independently of
row-list length. It is not a budget, wall-time or memory assertion about
Python, and it does not replace the running admission's 64-row cap.
