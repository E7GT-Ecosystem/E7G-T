# EEC-Q two-stage exact value and operational bridge (review candidate)

Baseline: main `0b1e292c59008cb7d0260ef85f3ae44f1df4d34f` (#104). This is a
provisional selected correlated binary FG3 Joint, not a new canonical profile.

## Exact admission and value map

`e7c_eecq_two_stage_b1.admit` is the only source admission gate. It checks the
registered editions and typed binary Joint, at most 64 canonical ordered rows,
unique support, canonical `AB`, `AC`, `BC` edge order, unrestricted Python `str`
or `None` graph tags, nonzero signed reduced `Fraction` with positive
denominator, and nonnegative integer step and ledger limits. The codec calls
that gate before reading rows. It refuses a noncanonical graph, coefficient or
row if used directly; no admitted tag string or integer numerator is excluded.

| Python source | Lean value | Exactness condition |
|---|---|---|
| `Config.edges` | `Graph.ab/ac/bc`, `WireGraph.edges` | Ordered subset of `AB, AC, BC`; inverse emits that order |
| `Config.tag` | `Option String` | `None` is `none`; `""` is `some ""`; all Python strings retained |
| Joint pair | `Row.left/right` | Both coordinates kept together; never recover a joint from marginals |
| `Fraction(n,d)` | `Row.coefficient : Rat` | Signed `n`, positive reduced `d`, no zero row; Python codec enforces canonical pair |
| ordered unique Joint terms | `List Row` | Row order is unchanged, unique support is an admission premise |
| first/second policy | `Policy` | Capability false wins over unresolved; else ready or undetermined |
| resource bounds | `Budget.stepBound/ledgerBound` | Arbitrary nonnegative Python integers map to Lean naturals |
| ledger event | `Event` | Attempt or stage/index/exact row/decision; ordinals verified in order |
| progress | `Progress` | Steps, ledger prefix, first exclusions and second exclusion prefix retained |
| second attempt start | `Machine.secondStarted` | Set when the step is charged, including failed append |

Lean `graph_roundtrip`, `canonical_row_roundtrip`,
`canonical_rows_injective`, `first_predicate_preserved`,
`second_predicate_preserved`, `ordered_three_way_mapping` and
`ir_preserves_exact_partition` cover the value-level projection, identity and
the three ordered partitions. They preserve the exact `Rat` in the row. The
Python codec verifies the reduced signed pair and roundtrips every admitted
row; Lean's `WireRow` itself stores a normalized `Rat`, not the unreduced input
spelling (which admission rejects). Invalid Python objects and JSON shapes
remain outside the theorem premises.

## Operational comparison and limits of proof

`staged_spec` charges a step before checking append space and visits a row
only after both resources allow it. It maps all four terminal outcomes, full
ordered events, exact progress, and `secondStarted`. The cross-language suite
compares source replay and independent IR execution against this staged rule
across empty and three-row supports, all 0..6 bounds, and both policies at
both stages. It also checks the exact one-row boundary `(step=4, ledger=2)`:
the second attempt charges step 3, fails append, leaves two first-stage ledger
events, has `firstExcluded=[]`, `secondStarted=true`, and no partition value.
The Lean theorem `failed_second_append_cross_language_fixture` evaluates the
same encoded row and bounds. `abstract_one_step_simulation` proves one step of
the Lean operational evaluator follows the independent Lean event plan.

**Still unproved:** a theorem over the actual Python interpreter and IR
implementations quantifying over all admitted inputs. Lean cannot import
their code; the source/IR-to-Lean transition correspondence currently has
executable differential coverage, not a machine-checked Python refinement
proof. Neither CI nor finite fixtures establishes that missing link. This gate
must stay provisional until the implementations are formalized or an
independently justified refinement relation is proved. It makes no domain
truth, product readiness or broader profile conformance claim.
