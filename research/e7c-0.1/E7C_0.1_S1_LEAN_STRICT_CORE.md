# S1 strict-union Lean control skeleton

Status: `bounded_first_party_candidate; abstract_fragment_only`

Base: main `a1bd47493a506ad81fa965c241d43c9a2fbc2c2f`.
Source reference: E7G-T v0.12.1/RGP2, unchanged.
Proof vehicle: provisional Lean 4.34.0; selection remains deferred.

`proof-packages/lean-core/E7CS1StrictCore.lean` adds a separate formal
model for the order in which a strict binary joint operation checks its
supported pairs. Each abstract pair has two nominal tags and one exact
integer coefficient. `run` charges one pair visit before comparing tags.
It returns one of three terminal constructors: success with the complete
ordered coefficient list, domain error, or resource limit. There is no
constructor carrying a partial success on either failure.

The formal source provides the following proofs:

| Theorem | Bounded statement |
|---|---|
| `empty_succeeds` | zero supported pairs return the empty complete value |
| `exhausted_before_first_check` | zero visit budget stops before any pair check |
| `incompatible_head_fails` | an inspected incompatible head gives whole domain failure |
| `sufficient_fuel_preserves_coefficients` | compatible supported pairs, with enough visits, return each original coefficient once in order |
| `sufficient_fuel_fails_whole` | one incompatible supported pair anywhere gives whole domain failure with enough visits |

This is a mechanised **control skeleton**, not a proof about the Python S1
runtime or the canonical EEC-Q algebra. Tags are natural numbers; amounts
are integers, not all rationals. Edge union, collision collection,
cancellation, admission before cancellation, static types, term-entry
steps, progress counters, detailed ledger and the translation between Lean
and Python are outside this model. It cannot discharge E7C-T017 or the S1
source-correspondence theorem recorded in
`E7C_0.1_S1_CORRESPONDENCE_GATE.md`. The next proof package must define a
typed refinement relation for those missing observations and show soundness
and bounded completeness for a selected S1 operation. No source/profile,
product, ID, schema, data or API migration occurs.
