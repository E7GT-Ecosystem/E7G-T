# WP5/IR: correlated FG3 Joint restriction (review candidate)

Base: main `124a8e573cb1490ce0d9a16238de20a5ce28a179`.
Source authority: published experimental v0.12.1/RGP2, X.5–X.6,
blob `a84da2c4de2ada23577cde4512a10c3369aba2b5`.
Example-model pin: FG3/0.1, blob `6c624fcd49b95e473a3e80160979183e8d3b58aa`.
Scope: opt-in, finite, graph-only, binary correlated Joint, fixed decidable
predicate “coordinate 0 lacks AB”, at most 64 canonical rows, with exact
signed rational coefficients.

The typed source adapter partitions whole Joint rows. Every tuple stays
together; coefficients appear exactly once. The source evaluator returns
both retained and excluded Joint states, plus the predicate edition. A
complete witness pins every input row, static type/effect, interpretation,
resource bounds, ordered decision ledger and terminal outcome. The versioned
IR independently traverses the exact rows and compares the entire terminal,
ledger and resource progress with the source witness after checking its
digest, source document and instruction pins. The ordinary `Fraction`
enumerator in the tests supplies a third, conventional comparison path.

Two joint tables with the **same two marginals** produce different retained
and excluded joint tuples. The tests also cover negative rationals, empty
typed joints, full exclusion, malformed later rows under a zero budget,
resource exhaustion before and during a row, capability `unsupported`,
predicate `undetermined`, and re-digested altered exclusion or terminal
claims. Resource limits return no successful partition; incomplete partial
decisions remain visible only as an ordered ledger prefix.

This selected predicate is a new profile-specific operation derived from
the canonical restriction rule. FG3's executable reference has a
graph-state `restrict_absent`, not a general executable Joint restriction.
Accordingly the conventional rational enumeration checks the new Joint
predicate, while older FG3 source differentials continue to check their
own published example fragment. There is no claim of an external reference
implementation for this new operation, general EEC-Q adequacy, proof of
compiler correctness, profile adoption, source truth, or product promotion.
Existing IDs, data, APIs, B1/B2/B3 editions and the canonical source do
not migrate.
