# E7C/0.1 formal vocabulary — WP1 review candidate

Status: `unfrozen_metalanguage_specification`. Not concrete syntax.

## 1. Universes and metavariables

Let `ProfileId`, `EditionId`, `TypeId`, `TermId`, `ModelId`, `CriterionId`,
`PolicyId`, `SourceId` and `WitnessId` be pairwise distinct identifier sorts.
They are nominal: equality of their serialised text is not cross-sort equality.

Indices used below have explicit meta-sorts:

| Metavariable | Meta-sort |
|---|---|
| `K` | `EntityKind` |
| `S` | `ConfigSignature` |
| `R` | `RepresentationContract` |
| `D` | `DomainPolicy` |
| `P` | `MapEdition` |
| `Q` | `InquiryId` |
| `H` | `HistoryPolicy` |
| `X` | `OutcomeExtensionEdition` |
| `E` | `EffectVocabularyEdition` |
| `J` | `JudgementClass` |
| `W` | `WitnessEdition` |
| `I` | `IndexSignature` |
| `B` | `ResourcePolicy` |

`A`, `B_t` and `V` range over well-formed types. The use of `B_t` for a type
is distinct from resource-policy metavariable `B`.

Let:

- `Delta` be a finite, immutable signature environment;
- `Gamma` be a finite typed variable/resource context;
- `Phi` be a finite collection of admitted constraints or outstanding proof
  obligations;
- `Epsilon` be a static effect bound;
- `Lambda` be a runtime effect/loss ledger;
- `M` be a pinned denotational model;
- `O` be a declared observation family;
- `kappa` be an inquiry/phase criterion.

The internal representation of contexts and effects remains open under
ADR-001 and ADR-004.

## 2. Signature environment

`Delta` is well formed only when every declaration has:

- a unique typed identifier and edition;
- an authority/status label (`canonical`, `candidate`, `proposal`, `local`);
- dependencies on earlier well-formed declarations;
- a declared mathematical kind;
- exported outcomes/effects/observations where applicable;
- no implicit import of truth, authority, access or canonical status.

Candidate judgement:

```math
\vdash \Delta\;\mathsf{sig}
```

## 3. Formation and typing judgements

The following judgement classes are distinct:

```math
\Delta \vdash A\;\mathsf{type}
```

```math
\Delta \vdash \Gamma\;\mathsf{ctx}
```

```math
\Delta;\Gamma \vdash \Phi\;\mathsf{admissible}
```

```math
\Delta;\Gamma;\Phi \vdash t:A \triangleright \varepsilon
```

The last judgement states a type and a static upper bound on effects. It does
not assert that `t` evaluates, succeeds, or denotes an externally true entity.

## 4. Admission and evaluation judgements

Value/input admission is separate from typing:

```math
\Delta;\Gamma;\Phi \vdash v \in_{\mathsf{adm}} A
```

Bounded evaluation, if later defined, must return exactly one terminal outcome
and one runtime ledger:

```math
\Delta;\Gamma;\Phi \vdash_{B} t \Downarrow (o,\lambda)
```

where `B` is an explicit resource policy. This is a judgement signature only;
WP1 supplies no evaluation rules. ADR-011 still decides whether malformed
external input is rejected before this relation.

## 5. Equality and equivalence judgements

Definitional equality:

```math
\Delta;\Gamma;\Phi \vdash t \equiv_{\mathsf{def}} u:A
```

Model-relative denotational equality:

```math
\Delta;\Gamma;\Phi \vdash_M t =_{\mathsf{den}} u:A
```

Observation-relative equivalence:

```math
\Delta;\Gamma;\Phi \vdash_O t \approx_{\mathsf{obs}} u:A
```

Inquiry-relative phase equivalence:

```math
\Delta;\Gamma;\Phi \vdash_\kappa t \sim_{\mathsf{phase}} u:A
```

The intended proof obligation is
`definitional equality => denotational equality in every admitted model`.
No other implication is built into WP1.

## 6. Candidate nucleus type families

These are typed vocabulary entries, not accepted concrete constructors:

| Family | Indices/parameters | Intended inhabitants | Excludes |
|---|---|---|---|
| `Entity[K]` | entity kind `K` | modelled referents identified under a declaration | descriptions or configurations by default |
| `Description[A,R]` | source type `A`, representation contract `R` | representations of `A` | identity with `A` |
| `Config[S]` | configuration signature `S` | admitted finite arrangements | formal sums or families |
| `Map[A,B_t,D,P]` | domain/codomain, domain policy, map edition | typed total or partial transformations | unchecked host functions |
| `View[A,V,Q]` | source/view types, inquiry `Q` | source-linked access with declared preservation/loss | source equality or access capability |
| `Encoding[A,R,S]` | semantic type, representation type, retention strength | governed representations with reconstruction claims | encryption or automatic SR4 |
| `History[A,H]` | state type, history policy | ordered transitions/outcomes | final-state-only identity |
| `Outcome[A,X]` | success type, extension-outcome family | terminal result alternatives | empty/zero values collapsed into failure |
| `Ledger[E]` | effect vocabulary edition | incurred effects/loss/resources | a static possibility bound |
| `Witness[J,W]` | judgement class, witness edition | replay material for a pinned claim | source truth or proof by checksum |

The following remain outside the nucleus in WP1: EEC-Q formal modules, SF
families, CFS nesting, RGP recursion/generation, WPC constitution, REC evidence
states and MSC scope diagrams. They are module/adapter candidates.

## 7. Typed candidate operation signatures

Every generic operation is indexed by a declaration or policy:

```math
\mathsf{apply}_{f}: A \to \mathsf{Outcome}[B_t,X_f]
```

```math
\mathsf{view}_{q}: A \to \mathsf{View}[A,V,Q]
```

```math
\mathsf{restrict}_{p}: \mathsf{Family}[I,A] \to
  \mathsf{Outcome}[\mathsf{Family}[J,A],X_p]
```

```math
\mathsf{reconstruct}_{r,B}: \mathsf{View}[A,V,Q] \to
  \mathsf{Outcome}[\mathsf{Fibre}[A],X_r]
```

```math
\mathsf{classify}_{\kappa}: \mathsf{Fibre}[A] \to
  \mathsf{Outcome}[\mathsf{Partition}_{\kappa}[A],X_\kappa]
```

`Family`, `Fibre` and `Partition` here are library-level typed interfaces, not
proof that they belong in the nucleus. `reconstruct` may return success only
when the declared finite fibre is complete; otherwise it returns a typed
non-success outcome.

## 8. Static effect vocabulary

An effect claim must identify a dimension and typed payload:

| Dimension | Payload obligation |
|---|---|
| partiality | domain policy and failure family |
| loss | preserved and lost observation identifiers |
| inquiry | criterion/inquiry identifier |
| access | required access capability; never inferred from a source reference |
| authority | required authority identifier and scope |
| alternatives | retained-choice/dependence policy |
| evidence | source, edition and dependence-group pins |
| history | history identity/order dependence |
| resources | finite bounds and exhaustion semantics |
| bridge | external/domain bridge and unverified obligation |

WP1 does not choose row, grade, lattice or product composition. Any WP2 choice
must define identity, preorder, sequential composition, branch join and runtime
ledger correspondence.

## 9. Outcome vocabulary

| Tag | Meaning | Must not mean |
|---|---|---|
| `success(a,w)` | value `a` produced under a declared contract, optionally with witness `w` | external truth or completeness beyond the contract |
| `type_error(d)` | no well-typed term under the selected rules | domain failure |
| `domain_error(d)` | typed operation is not defined for admitted operand | successful empty output |
| `unsupported(c)` | required capability is absent from this fragment | false or impossible |
| `undetermined(p)` | an obligation remains unresolved | success or resource exhaustion |
| `resource_limit(b,p)` | bound `b` stopped evaluation with progress record `p` | mathematical invalidity |
| `invalid_input(d)` | malformed external representation | settled as operational; ADR-011 remains open |

Profile modules may extend outcomes only through a disjoint, editioned family.

## 10. Module and adapter judgements

```math
\Delta \vdash P@e\;\mathsf{module}
```

```math
\Delta \vdash F:P@e \Rightarrow C@c\;[d]
```

where disposition `d` is exactly one of `faithful_embedding`,
`faithful_interpretation_with_explicit_loss`, `partial_translation`, or
`unsupported`. A non-lossless disposition must name its observation family,
quotient/loss relation and rejected source cases.

## 11. Proof-status vocabulary

Only these statuses may annotate WP1 theorem obligations:

- `not_started`;
- `statement_drafted`;
- `proof_sketch`;
- `mechanised_for_fragment`;
- `externally_reviewed_for_fragment`;
- `counterexample_known`.

No WP1 statement currently exceeds `statement_drafted`.
