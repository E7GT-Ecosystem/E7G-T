## Sort execution model

`E7CJointSortConstructorSemantics.lean` defines an abstract comparison-and-
insertion semantics. Its trace records comparisons and list insertions as
model events; it is not asserted to be CPython's actual comparison or write
sequence, and it does not model Timsort. Lean derives the sorted model result
from this trace.

The composition theorem consumes a separate `PreSortJointHelperTrace`, which
contains only the dictionary-loop and nonzero-filter observations. It does not
accept #144's full `CPythonJointHelperTrace`, so it has neither that record's
`sortResult` nor `constructorCopiesTerms` premise. An explicit abstract sort
trace derives the sorted keys; mapping those keys to rows yields the normalizer,
and the constructor check/run composes over that derived sequence. The separate
CPython host link remains open: key extraction, tuple comparison, and built-in
`sorted` must be related to this abstract semantics.

The Lean comparator cases establish AB before AC and a null tag before an
empty-string tag. The test suite checks the full three-edge order, the same
tag distinction, duplicate aggregation, exact rational coefficients,
cancellation, and constructor rejection.

## Constructor execution model

`runConstructorRows` checks positive arity, the outer tuple, each modeled
row's atom-tuple/exact-Fraction/nonzero conditions, and the canonical-order
check. On success, this model returns its input row sequence after those
checks; a failed row check or false canonical-order result derives rejection.
The constructor portion is intentionally stated at this model level. The
adapter tests show rejection of invalid Python objects (including bool-versus-
int cases), but those objects are not represented by the typed `Row` carrier;
treat their rejection as test evidence until an untyped admission model is
added. Runtime validation and CPython adequacy remain open.
