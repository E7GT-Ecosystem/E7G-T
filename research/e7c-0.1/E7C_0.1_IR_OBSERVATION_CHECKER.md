## What the new theorem checks

`certify` consumes decoded packets with distinct charge, append and final
terminal records. It checks charged steps and second-start state, the exact
expected row/event and ledger count, both resource counters, and the complete
terminal observation. It constructs the existing indexed `Trace` proof by
recursion; it does not require a supplied completed Trace. Missing, reordered,
additional or changed packets reject. A resource terminal carries progress,
never a partial successful partition.

Public `checkStream` returns an ordinary observation. Its soundness theorem
uses checker acceptance to derive equality with the existing fuelled Lean
machine. Accepted source and IR streams agree and retain the exact wire plan's
budgeted prefix. This is for every decoded stream and selected modeled state,
not a finite-list-only theorem. The row events carry both correlated graph
coordinates and the exact rational value.

`packageGate` distinguishes nested-limit, outer-limit and admitted cases.
`checkIR` rejects either exceeded bound. Its theorem derives both separate
1,000,000-byte inequalities from acceptance. The lengths must be separately
measured serialized lengths, not inferred from source admission. This gate
does not implement native serialization and its rejection is not an EEC-Q
resource-limit outcome. If both fail, nested rejection is reported first,
matching the nested lowering order. The zero/exact/one-over cases stay separate.

The failed-second-append lemma checks an arbitrary second-attempt cursor:
one step is charged, no event is appended and secondStarted becomes true.
It is a checker/model boundary result, not a native-host execution theorem.

## Running-code instances and trust boundary

`check_e7c_ir_observations.py` freshly executes the source and independent IR,
retains their separate transition streams, structurally decodes reported terminal
observations and rows, measures each actual serialized package, and
emits Lean literals. Hosted Lean checks source/IR stream acceptance and
bounded IR acceptance separately for each document. No completed Trace
certificate is provided in those generated propositions.

Seven documents cover signed fractions, null versus empty tags, success,
empty support, zero steps, policy stops and exhaustion. The required one-row
four-step/two-entry failure charges step 3 without append and starts stage two.
Finite generated-literal checks are instance evidence. The exporter, raw
decoder, stable native bindings, complete/provenance-correct capture and
native event production are trusted or open. The structural decoder is not
proved equivalent to native observation semantics here.
No normal-return adequacy for all admitted running inputs is claimed.

## Emitted-row transport increment

Based on #164 at `3c5b2ab928717738e6f32aae8e80ca547ed78b55`.
`WireEvent` carries the emitted canonical edge lists, nullable tags, signed
reduced rational value, stage, index and decision. `decodeEvent` maps those
fields to the checker event. Lean proves event round trip and recovery of
canonical wire row events; no correlated coordinate or coefficient is dropped.
`checkTransport` derives drive agreement from checked transported packets,
and `checkTransportIR` additionally derives both independent byte bounds.

The exporter no longer calls the Python transition certificate checker.
It parses each append record's own `row_key`; it never replaces that payload
with a row selected from the expected input or projected ledger. Wrong charge
counts and changed row values reach Lean unchanged, where checker rejection
is checked. Five fresh forgeries cover changed charge, missing charge,
duplicate terminal, false second-start and changed signed coefficient.

This is a structural carrier and instance transport result, not a theorem
about raw JSON parsing or the running emitters. JSON decoding, canonical
row admission, terminal projection, metadata omitted from Packet, native
capture completeness/provenance and byte measurement remain explicit trusted
or open boundaries. In particular this increment does not prove that every
normal native execution emits a stream accepted by the checker. The decoder
rejects unreduced fractions rather than silently normalizing them.

## Terminal transport increment

Based on #165 at `4915e611e75baca3ca3de60047a6e09f325ba002`.
`WireProgress`, `WireTerminal` and `WireObservation` carry their reported rows
and event payloads. Resource terminal progress remains separate from the
top-level progress, and each ledger retains its own order. The terminal
start bit comes from the terminal capture, not a count-based inference.
Lean proves encode/decode round trip for every modeled observation, including
success, resource limit, unsupported and undetermined outcomes. Accepted
terminal-carrier streams refine the drive; bounded IR acceptance also
requires both measured package lengths to meet their separate bounds.

The exporter no longer uses the old semantic terminal projection. Its
structural decoder reads the reported partition, ledger and progress without
comparing them to an expected input-table partition, policy result or plan.
Five new terminal forgeries reach Lean for rejection alongside the earlier
five stream forgeries. Native invalid-input admission and reduced fraction
validation still use the existing row codec; raw fractions are not silently
identified by normalization. This is not a raw JSON parser proof.

Remaining boundaries include raw JSON/row decoding, ignored static metadata,
native statement/emit semantics, complete and provenance-correct captures,
separate measured-byte transport, stable bindings and normal host completion.
No theorem yet establishes that every admitted native normal return supplies
an accepted stream. No exception, nontermination or native resource
classification theorem is added. Existing product IDs, APIs and IR pins
are retained; this changes only the opt-in research checker/exporter.
