# E7C/0.1 bounded static semantics — WP2 review candidate

Status: `wp2_static_semantics_drafted_unfrozen`

Authority: WP1 accepted at PR #35 head `b1c8ca7…`, merged as `1f4c7cf…`

Canonical baseline: E7G-T v0.12.1-experimental, `RGP/0.1`, revision RGP2

This document specifies the first finite E7C-B1/0.1 static fragment. It defines
an abstract JSON syntax and executable type-and-effect checks. It does not define evaluation,
denotation, witnesses, a stable interchange schema, a runtime/API, or any
profile adapter.

## 1. Bounded fragment

The fragment contains nine type constructors and six term constructors:

```text
Type ::= Base[name]
       | Entity[kind]
       | Config[signature]
       | Map[source,target,domain-policy,map-edition]
       | View[source,view-type,inquiry]
       | Family[index,element]
       | Fibre[source,reconstruction-policy]
       | Partition[source,criterion]
       | Outcome[success-type,outcome-extension]

Term ::= var(name)
       | apply(map-declaration, term)
       | view(view-policy, term)
       | restrict(restriction-policy, term)
       | reconstruct(reconstruction-policy, resource-policy, term)
       | classify(criterion, term)
```

`Base` is an opaque declared carrier name, not an undifferentiated runtime
value. Every other argument position is fixed as either a nested type or a
nominal identifier. Unknown constructors, wrong arities, empty identifiers and
extra fields are malformed input.

Diagnostic and result rendering preserves every type constructor and encodes
each nominal identifier as a JSON string. Consequently rendering is injective
over admitted type trees even when identifiers contain commas, brackets,
quotation marks or constructor-like text.

The JSON representation is an internal research AST. It is deliberately not a
concrete language syntax or stable public schema.

## 2. Environments and declarations

The checker admits one environment with exact sections for
variables, maps, views, restrictions, reconstructions and criteria. The
following declaration shapes are closed in E7C-B1/0.1:

| Declaration | Required fields |
|---|---|
| variable | exact type |
| map | source, target, domain policy, map edition, outcome extension |
| view | source, target, inquiry, explicit loss list |
| restriction | input index, output index, element type, outcome extension |
| reconstruction | source, view type, inquiry, admitted resource policies, outcome extension |
| criterion | exact input type, outcome extension |

All referenced declarations are resolved by exact nominal identifier. A text
match across different identifier positions does not create cross-sort
equality or authority. Admission snapshots every declaration body, so later
mutation of a caller-owned environment cannot alter checking behaviour.

## 3. Context boundary

The executable fragment has no binders. Its variable context is finite,
immutable and reusable. Consequently it exercises lookup and exchange but does
not claim linearity, affinity, substitution, weakening for binders, or closure
of ADR-001. Any later binder or consumable resource requires a separate context
discipline and proof obligations.

## 4. Type equality and conversion

E7C-B1 type conversion is structural equality of parsed canonical type trees:

```math
A \equiv^{B1}_{\mathsf{def}} B \quad\text{iff}\quad
\mathsf{parseType}(A)=\mathsf{parseType}(B).
```

There are no aliases, reductions, coercions, subtyping rules or user equations.
Denotational, observational, phase, representation and reconstruction
relations are never consulted by the checker. This is a bounded candidate for
ADR-002, not a decision for the abstract calculus.

## 5. Effects

The static effect carrier is a finite set of typed atoms
`dimension(payload)`, canonically sorted for output. Its dimensions are exactly
the ten WP1 dimensions: partiality, loss, inquiry, access, authority,
alternatives, evidence, history, resources and bridge.

For this fragment, composition is idempotent union:

```math
\varnothing \mathbin{\sqcup} \varepsilon = \varepsilon
\qquad
\varepsilon_1 \mathbin{\sqcup} \varepsilon_2
  = \varepsilon_1 \cup \varepsilon_2.
```

This supplies identity, associativity, commutativity and idempotence for the
implemented straight-line rules. It does not define effect masking, sequential
runtime ledgers, branch joins with path sensitivity, subeffecting, parallel
composition or a general answer to ADR-004.

## 6. Domain policies

Map declarations and `Map` type annotations admit exactly `total`, `strict` or
`filtering`. `strict` and
`filtering` add a `partiality(policy@edition)` effect. `total` adds no
partiality effect. The distinction is static only: WP2 does not define which
values inhabit a domain or how failure/filtering evaluates. Silent mixing of
the three policies is rejected; their dynamic meaning remains for WP3 and
ADR-005 review.

## 7. Typing rules

Below, `eff(t)` is the already checked effect row of `t` and `⊔` is finite
effect union.

### Variable

```math
\frac{x:A \in \Gamma}
     {\Delta;\Gamma;\Phi \vdash x:A \triangleright \varnothing}
```

### Map application

For `f:MapDeclaration[A,B,delta,mu]` with outcome extension `xi_f`:

```math
\frac{\Delta;\Gamma;\Phi \vdash t:A \triangleright \varepsilon}
     {\Delta;\Gamma;\Phi \vdash apply_f(t):Outcome[B,xi_f]
       \triangleright \varepsilon \sqcup partiality(delta@mu)}
```

The partiality atom is omitted only for `delta = total`.

### View

For `q:ViewPolicy[A,V,iota]` with declared loss set `L_q`:

```math
\frac{\Delta;\Gamma;\Phi \vdash t:A \triangleright \varepsilon}
     {\Delta;\Gamma;\Phi \vdash view_q(t):View[A,V,iota]
       \triangleright \varepsilon \sqcup inquiry(iota) \sqcup loss(L_q)}
```

The loss atom is omitted exactly when the declared loss list is empty. Source
identity remains in the result type.

### Restriction

For `p:RestrictionPolicy[I,J,A]` with extension `xi_p`:

```math
\frac{\Delta;\Gamma;\Phi \vdash t:Family[I,A] \triangleright \varepsilon}
     {\Delta;\Gamma;\Phi \vdash restrict_p(t):Outcome[Family[J,A],xi_p]
       \triangleright \varepsilon \sqcup alternatives(p)}
```

### Reconstruction

For `r:ReconstructionPolicy[A,V,iota]`, admitted resource policy `beta` and
extension `xi_r`:

```math
\frac{\Delta;\Gamma;\Phi \vdash t:View[A,V,iota] \triangleright \varepsilon}
     {\Delta;\Gamma;\Phi \vdash reconstruct_{r,beta}(t):
       Outcome[Fibre[A,r],xi_r]
       \triangleright \varepsilon \sqcup resources(beta)
       \sqcup alternatives(r)}
```

This rule types a request for the exact declared fibre; it does not certify
completeness or produce the fibre. Only WP3 evaluation may return success, and
then only under the WP1 exact-fibre control.

### Classification

For criterion `kappa` with exact input type `A` and extension `xi_k`:

```math
\frac{\Delta;\Gamma;\Phi \vdash t:A \triangleright \varepsilon}
     {\Delta;\Gamma;\Phi \vdash classify_k(t):
       Outcome[Partition[A,kappa],xi_k]
       \triangleright \varepsilon \sqcup inquiry(kappa)}
```

The rule does not license representative-independent application to a phase.

## 8. Admission and diagnostics

Admission is layered before typing:

1. document and AST shape;
2. type-constructor formation and arity;
3. environment/declaration shape;
4. closed domain-policy and effect vocabularies;
5. nominal declaration resolution;
6. exact operand type checking.

Malformed representations return structured `invalid_input` diagnostics with
codes `E7C-S001`–`E7C-S010`. Well-shaped but ill-typed terms return structured
`type_error` diagnostics `E7C-T001`–`E7C-T003`. These are checker results, not
runtime `Outcome` values. This is the E7C-B1 candidate boundary for ADR-011;
WP3 must separately decide how admitted terms produce operational outcomes.

The checker never executes arbitrary host-language strings, invokes an
evaluator, checks source truth, infers authority, or treats a successful static
check as evidence of evaluation success.

## 9. Executable correspondence

`e7c_b1_static.py` is the dependency-free executable counterpart. The fixture
suite covers every term constructor and includes unknown identifiers, operand
type mismatches, family-index mismatch, unadmitted resource policy, malformed
term tags, extra fields and unknown domain policies.

The executable checker is a disposable research prototype. A later schema or
API must not claim compatibility merely because it reuses these JSON field
names.

## 10. WP2 review gate

WP2 may pass only when review confirms:

- every admitted AST/type form has a formation rule;
- every term constructor has one deterministic type-and-effect rule;
- all positive fixtures are machine checked;
- malformed and ill-typed fixtures fail through controlled diagnostics;
- source/view, family indices, reconstruction policy and resource policy remain
  identity-bound;
- no denotational, observational or phase equality enters conversion;
- no dynamic, denotational, witness, IR, runtime, API or product claim is
  smuggled into the static checker.

Acceptance authorizes a separately scoped WP3 specification. It does not
authorize canonical promotion or product migration.
