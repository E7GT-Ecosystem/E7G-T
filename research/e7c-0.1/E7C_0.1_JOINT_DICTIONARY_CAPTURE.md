## Captured operations

`e7c_joint_dict_aggregation_capture.py` calls the original `joint(terms,
arity=2)` body. It combines:

- `sys.settrace` line events at the pinned dictionary assignment to record the
  ordered accumulator before and after each row;
- `sys.setprofile` events for the built-in dictionary `get` call;
- the actual `Fraction(0)` default construction, `Fraction.__add__` call
  operands and return value;
- `Fraction.__bool__` calls and results in the generator's zero filter; and
- the exact terms passed into `Joint` and its post-init return.

The original input row order is retained. The regression uses equal-but-distinct
`Config` objects as repeated keys, accumulates `1/3 + 1/6`, cancels that total
with `-1/2`, and preserves a second ordered pair with coefficient `2/5`. The
receipt shows dictionary sizes `1, 1, 1, 2`, exact post-add values `1/3, 1/2,
0, 2/5`, a false zero-test for the cancelled entry, and only the nonzero row
passed to the constructor. A separate negative case confirms the actual Joint
constructor rejects unsorted terms.

## Proof boundary

| Operation | Observed in this finite run | Still assumed/open |
|---|---|---|
| Input row visit | Each ordered tuple row at the dictionary update statement | All-input Python iteration/order adequacy and mutation exclusion |
| `dict.get` | Actual built-in `get` call, receiver identity, key and accumulator snapshot | Internal hash probes, collision resolution, Config `__hash__`/`__eq__`, and direct return value; the subsequent Fraction addition's left operand is observed |
| Fraction default and addition | `Fraction(0)` arguments, addition operands and exact returned Fraction | All-input `Fraction` arithmetic and constructor/failure semantics; profiler/event denotation is trusted |
| Dictionary assignment | Accumulator states immediately before and after the pinned source statement | The bytecode stack transition and universal assignment semantics; the statement AST remains syntax-pinned |
| Cancellation filter | Actual `Fraction.__bool__` result for each generator candidate | All-input truth-test adequacy and exception/resource behavior |
| Sorting handoff | Exact terms supplied to the `Joint` initializer after the source's `sorted(...)` expression | CPython sorted adequacy and its comparison/write sequence. Lean's insertion-sort trace remains an abstract model only |
| Joint validation | Actual initializer and post-init frame boundary | All-input validation/rejection and output-copy semantics |
| Host completion | Packet emitted only after normal return; hooks restored in `finally` | Termination, sufficient resources, asynchronous interruption, and classification of exceptions/resource stops |

This is finite profiler/tracer evidence for Python 3.12.14 in the recorded
runtime. Both observers and their event interpretation remain trusted. It does
not provide an all-input bridge from CPython to
`PreSortJointHelperTrace` or `JointNormalizerStatementTrace`. The bounded #173
event composition and #174 receipt decoder check one supplied finite
transition sequence against the dictionary model, conditional on the RawJson
and event observations. They do not prove general normal-return correspondence
or EEC-Q implementation conformance.
