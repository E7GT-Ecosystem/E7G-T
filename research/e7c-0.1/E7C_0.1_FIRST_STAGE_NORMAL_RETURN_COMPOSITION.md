## Fuel and canonical-row boundaries

The JSON-value model's row decoder includes a 32-fuel check absent from the pinned Python admission code. This increment keeps RawRowsAdmissionStatementTrace.fuelCheck explicit. The theorem therefore covers the subset of successful Python-shaped row traces that also satisfy this model check. It does not claim the restriction is redundant for every row shape accepted by Python. Deriving a fixed-depth bound from the schema visits and removing this narrowing is still open.

The previous prefix requires CanonicalWireRows to derive exact typed parser identity. The composed raw-JSON equality theorem does not assume that property, but this increment does not yet prove it from canonicalEdges either. Accordingly it does not claim exact decoded-row-to-typed-row correspondence for every source row. Deriving CanonicalWireRows from the admission edge checks remains an open proof obligation.

## CPython premises not discharged by Lean

| Host operation/link | Required premise to interpret the event trace as running CPython |
|---|---|
| JSON parsing and object admission | json.loads produces the modeled scalar/array/object observations; object key behavior and duplicate-key policy match the pinned path |
| Exact type checks | type(x) is int and exact container checks reject bool/subclasses and match the recorded booleans |
| Fraction construction | Fraction(n, d) accepts the traced integers, yields the exact rational, reduces pairs as Python does, and follows the modeled exception branch |
| Config construction | Config(edges, tag) yields the modeled graph and preserves None versus ""; its validation outcome matches the trace |
| Dictionary aggregation | Hashing, key equality, lookup, addition, assignment, cancellation, and zero filtering match the operation model, including collision handling |
| Stable bindings | Helper names, imported classes, equality/hash behavior and relevant objects are not rebound or mutated during the run |
| Sorting | Python key extraction, tuple comparison, and built-in sorted produce the abstract trace's order; the abstract insertion writes are not claimed to be CPython's actual Timsort comparisons or writes |
| Joint construction | Exact type, arity, atom, Fraction, nonzero and ordering checks match; successful construction preserves the operation's rows as modeled |
| Row serialization | Attribute reads, dict/list writes, exact numerator/denominator and row order match the serializer trace |
| Final equality | Python equality on precisely (serialized output, admitted original rows) agrees with the fuel-bounded recursive extensional object-key relation |
| Normal host completion | Every call terminates normally with sufficient memory/stack/time and without an uncaught exception, cancellation or external resource interruption |

The Lean theorem consumes modeled event traces and equality adequacy for the compared pair. The table lists the separate host evidence still needed to establish that a running Python execution supplies those traces. No host exception, divergence, or resource interruption is identified with invalid input or normal return; the Lean outcome constructors remain distinct.

## Focused countercases

The existing focused raw-admission and serializer fixtures exercise:
- recursively reordered object keys as equal while retaining order for arrays and rows;
- noncanonical edge sequences as rejected;
- an unreduced raw pair such as 2/4 as distinct from canonical 1/2;
- row/coordinate/edge order, and null tag versus empty string;
- the 65-row cap as an admission failure.

These are regression evidence for the Python adapter and equality model, not a proof of CPython primitive adequacy.
