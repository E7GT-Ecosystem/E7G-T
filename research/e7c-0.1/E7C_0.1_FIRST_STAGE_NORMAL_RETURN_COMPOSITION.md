## Derived canonicality and fuel bound

The restored `canonicalEdges` is the pinned recursive validator: each edge is registered and adjacent edge ranks strictly increase. A finite-classification lemma proves that every accepted input is among the eight subsets of `AB`, `AC`, and `BC` in increasing rank order; it does not state the converse. `canonicalEdges_implies_canonicalGraph` discharges the graph round trip by those cases. The row visit induction derives `CanonicalWireRows` for every admitted row, and the first-stage theorem now includes both the `ParseRowsCall` and the exact `parseRows rows = rows.map toRow` identity. Noncanonical order and malformed nested shapes have Lean counterexamples; the existing rational-pair, object-key permutation, array/row/coordinate/edge order, null/empty tag, and row-cap regressions remain.

The row trace no longer has a `fuelCheck` field. From exact two-key layout and the successful edge-string, tag, integer, two-coordinate, graph, and fraction operations, the Lean proof derives depth bounds of 2 for graphs/fractions, 4 for rows, and 5 for the rows array. Monotonicity gives `rawJsonWithinFuel 32` for the admitted source array. Thus the model's legacy 32-fuel guard is redundant on every trace represented by the accepted row schema; it is not an additional admission premise and it is not a Python check.

| Stable bindings | The helper names, constructors, imported Fraction class, key functions, equality/hash methods and relevant objects retain the pinned meanings throughout execution. |
| Sorting | The pinned key extraction, tuple ordering and CPython `sorted` result agree with the abstract identity-sort result. Lean's insertion trace is not asserted to be CPython's comparison/write sequence. |
| Joint construction | The pinned constructor's type, arity, coordinate, Fraction, nonzero, ordering checks and returned row sequence agree with the constructor trace. |
| Row serialization | Attribute reads and dictionary/list writes produce the modeled serialized rows with exact rational fields and row order. |
| Final equality | For the exact pair (serialized output, admitted original rows), Python `==` agrees with the fuel-bounded recursive object-key relation. The fuel safety of both sides is derived by Lean from the row traces. |
| Normal host completion | The traced operation sequence terminates normally with sufficient memory, stack and time, and without an uncaught exception, cancellation or external resource interruption. This is a separate conditional premise. |

The Lean theorem consumes modeled operation traces and the compared-pair equality contract. The premises above are still required to show that a running CPython execution supplies those traces. The host-outcome constructors only keep labels distinct inside the model; they do not prove that Python classifies exceptions, nontermination or resource interruption into those labels.
