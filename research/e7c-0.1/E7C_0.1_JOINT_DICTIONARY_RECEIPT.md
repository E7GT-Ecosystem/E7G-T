## What is derived

Given a parsed `RawJson` receipt and the explicit successful decoder result, Lean decodes:

- the binary key as two canonical Config graphs, preserving tag absence versus an empty string;
- reduced signed numerator/positive denominator Fraction pairs, matching Python Fraction's canonical fields;
- ordered pre-update and post-update dictionary entry lists; and
- row events in list order with consecutive indices.

For each decoded event, the decoder requires the observed lookup result to equal the model lookup, the addition result to equal the modeled exact sum, and the after-state to equal `dictSet`. Thus an accepted event sequence constructs `JointDictionaryEventTrace`; `acceptedPacket_has_modelled_final_dictionary` derives the final state from the modeled fold. Malformed shapes, booleans in fraction pairs, and noncanonical edge lists are rejected by Lean lemmas; the decoder checks that Fraction fields are already reduced.

The capture receipt now groups the existing line and profiler observations into one row transition: row, prior state, Fraction-add left operand, Fraction-add return, observed dict.get call marker, and resulting state. Tests exercise duplicate equal keys from distinct Config instances, exact 1/3 + 1/6, cancellation by -1/2, zero and nonzero outcomes, ordered rows, and exact rational pairs.

## Proof boundary

| Link | Status |
| --- | --- |
| Decoded transition fields satisfy the abstract Lean dictionary step | Derived by the Lean decoder's checks |
| Transition order and composition into a Lean trace | Derived from list order, consecutive indices and state chaining |
| Fraction operations in this finite capture | Values are captured and checked against the exact rational model; universal CPython Fraction adequacy remains open |
| `dict.get` return equals the Fraction-add left operand | Open CPython expression-evaluation premise; receipt records the call and left operand separately |
| CPython dictionary update equals the decoded before/after mapping, including hash/equality and insertion order | Open operation adequacy beyond this finite receipt; Lean checks only that the supplied states satisfy its model |
| Profiler/trace callbacks faithfully identify the pinned operation events | Open trusted instrumentation/CPython premise |
| JSON text parser to Lean `RawJson` | Open; theorem begins after a RawJson value is supplied |
| Pinned module bindings, unmodified source, row visits, normal host completion and sufficient resources | Open host premises; no theorem here classifies exceptions or resource interruption |
| Zero filtering, sorting, constructor behavior, raw admission, serializer/final guard, independent IR | Outside this increment and still outstanding |

The packet decoder is conditional evidence processing. It does not promote one captured run into a universal CPython semantics theorem.
