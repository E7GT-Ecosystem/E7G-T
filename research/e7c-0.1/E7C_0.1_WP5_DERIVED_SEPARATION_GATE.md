The selected test carrier is the already implemented eight untagged FG3
graphs. The component views retain the three named node occurrences and
hide their pairwise connecting edges. The existing FG3 edge-count quotient
adds a declared global summary; the existing finite-fibre operation finds
every graph compatible with it **relative to the complete fixed basis**.
The protected inquiry is either edge count or the presence of `AB`. The
semantic context and inquiry must be explicitly named. This is an
illustrative labelled-graph fragment, not a translation, legal-effect or
physical-domain model.

The three statuses are derived without a new E7C constructor:

| Status | Finite condition | Consequence |
| --- | --- | --- |
| `separable` | Every complete-fibre candidate preserves the protected property | Return the complete compatible class **only modulo that criterion**; do not choose or invent exact hidden edges. |
| `non_separable` | Two view-compatible graphs differ on the protected property | Return the source/alternative pair as a material hidden-relation witness. |
| `undetermined` | Resource bound stops full scanning or the declared carrier is not the reviewed complete basis | Return no positive or negative separation conclusion. |

The tests enumerate all eight graphs for both protected inquiries, verify
same-view/different-`AB` witnesses, preserve the full compatible class
without claiming exact source return, and reject truncated carrier,
resource exhaustion, edition mismatch, tagged graphs and an unregistered
criterion. They use the already implemented `identify_phase` and
`reconstruct_fibre` operations; no coefficient is interpreted as a physical
relation, evidence weight, probability or support value.

This demonstrates definability **in the selected finite fragment only**.
The node-only component views and edge-count summary do not settle the
proposal for arbitrary components, protected structures or reconstruction
procedures. A wider result remains deferred; no counterexample here forces
a new core primitive. No canonical kernel, data, API or product migration
is proposed. Passing this first-party test is not independent validation.
