# First-stage admission operation semantics

This note is a refinement specification for the pinned normal-return path in
`e7c_eecq_joint_restrict_b1.py`. It is not a theorem that CPython executes
according to the specification. The generated Lean result remains
`E7CJointAdmissionSemantics.normal_return_exact_rows`, and the call derivation
remains `E7CJointAdmissionCalls.NormalReturn` in the reviewed #135 head.

## Mathematical operations

| Python operation | Successful mathematical meaning | Exceptional cases outside normal return |
|---|---|---|
| `Fraction(n,d)` | For exact integers `n,d` and `d > 0`, return the unique reduced rational `n/d`; denominator is positive. | `d = 0` raises `ZeroDivisionError`; wrong operand types or unsupported conversions raise `TypeError`/`ValueError`; allocation/resource exhaustion may interrupt. The parser's earlier guards exclude non-integers, nonpositive `d`, and zero numerator. |
| `Config(tuple(edges), tag)` | Check every edge is one of `AB, AC, BC`, check `tag` is `None` or `str`, then store `sorted(set(edges))` and the same tag. Equality is structural equality of the frozen dataclass fields. | Invalid edge/tag raises `AdmissionError`; tuple allocation/sort may exhaust host resources. Input graph is accepted only if `_graph(config) == original_wire_graph`, so unsorted or duplicated wire edges are rejected. |
| `joint(parsed, arity=2)` | Visit each `(Fraction, (Config, Config))` in order; use the ordered pair of Config values as key; add exact coefficients for equal keys; drop zero totals; sort unique keys by the module's identity tuple; construct `Joint(2, terms)`. | Wrong list/row/arity/config/coefficient types, mixed arity, or invalid Joint invariant raises `AdmissionError`; allocation or sorting can fail. |
| row iteration | `for row in source['rows']` visits each list element once in list order; `for g in atoms` and `tuple(graphs)` preserve element order. | Mutation during iteration, a substituted object, or interruption is outside the stable-input normal path. |
| `rows(value)` | Check `type(value) is Joint` and arity 2; iterate `value.terms` in order and emit each ordered pair's two graphs and reduced coefficient numerator/denominator. `_graph` writes canonical edge order and preserves the nullable tag. | Wrong Joint/arity raises `JointRestrictionAdmission`; helper substitution or interruption is outside the premises. |
| list/dict equality | Built-in equality compares lists positionally and dictionaries by equal key/value mappings; nested tags distinguish `None` from `""`; integer numerator/denominator fields compare exactly. The guard succeeds iff serialized rows equal source rows. | Custom equality methods, mutation, replaced bindings, or exceptions are excluded by exact built-in type and stable-binding premises. |

The operation specification does not assume that the guard succeeds. For an
admitted wire list `w`, let `parse(w)` construct typed rows, `J` aggregate them,
and `ser` serialize them. The program's normal return is derived only when
`ser(J(parse(w))) = w`. The Lean theorem then derives
`J(parse(w)) = w.map toRow` and preserves both correlated coordinates, tags,
order, and exact rational values.

## Local CPython refinement premises

The following are the only host-level premises needed for this selected
normal-return slice. They are individually checkable and do not state the
resulting serialized rows or the final equality:

1. **Primitive arithmetic:** for exact built-in `int` values `n` and `d > 0`,
   the pinned `fractions.Fraction(n,d)` returns the reduced exact pair with
   value `n/d`; for `d = 0` it raises `ZeroDivisionError`. Exact Fraction add,
   equality, and truth testing implement rational addition, equality, and
   zero testing.
2. **Dataclass construction:** the pinned frozen `Config` initializer checks
   exact tuple/string/null types and registered edges; its post-init stores
   `tuple(sorted(set(edges)))`; generated equality compares the two fields.
   `Joint` construction checks exact arity, tuple, Config and Fraction types,
   nonzero coefficients, and sorted unique support.
3. **Container primitives:** with exact built-in list, tuple, dict, str, int,
   bool, and `None` objects and no concurrent mutation, iteration yields the
   elements in their stored order; tuple construction preserves that order;
   list/dict structural equality has the meanings in the table.
4. **Call identity:** the imported `Fraction`, `Config`, `Joint`, `joint`,
   `_graph`, `_row`, `rows`, and built-in container/equality bindings are the
   pinned bindings during the call; no monkeypatch, rebinding, custom object,
   or callback mutates the source or intermediate values.
5. **Normal execution/resources:** all described operations terminate,
   complete their allocations/sorts, and return without an exception, signal,
   process termination, memory exhaustion, recursion failure, or external
   interruption. Parser-caught admission exceptions are non-normal returns.

These premises describe operation outcomes and runtime stability. None says
that `ser(J(parse(w)))` equals `w`; that equality is a conclusion of the
running guard. The AST fingerprint proves source-site identity only.

## Derivation and adversarial observations

On a normal return, exact parsing yields `parse(w)`, aggregation yields the
mathematical `J(parse(w))`, `rows` yields its serialization, and built-in list
equality evaluates the actual guard. The pinned `admit` return can occur only
when that equality is true. The existing Lean theorem
`normal_return_exact_rows` then proves every returned row has the original
ordered pair and coefficient, including the full correlation; this is an
all-list theorem over exact `Rat`, not a finite fixture theorem.

| Adversarial change | Why normal return is rejected |
|---|---|
| Change a coefficient in the input | It denotes a correspondingly different admitted Joint; the all-list theorem preserves that new exact coefficient. Changing the computed Joint behind the guard changes the serialized field and cannot be a normal return. |
| Replace correlated `(left,right)` rows with marginals or crossed pairs | each ordered pair is parsed and serialized intact; a different pair denotes different support. The theorem does not identify it with the original correlation. |
| Change a tag (`None` to `""`, or another string) | Config equality and `_graph` preserve the changed tag as a distinct admitted value. The theorem retains the exact tag. |
| Reorder rows | Joint returns canonical key order and list equality is positional; a noncanonical wire order differs. |
| Duplicate/cancel rows | Joint sums equal keys, removes zero totals, then `rows(value) != source['rows']`; parser rejects duplicate/cancelled representation. |
| Forge serialized output by replacing `rows` | This violates the fixed-binding premise; executable regression demonstrates it can mask a changed Joint and is not covered by the theorem. |

The checked-in Python tests directly cover signed `-2/3`, null/empty tags,
and forged serializer binding. Additional normal-path regression cases cover
changed coefficient, swapped correlation, row order, and duplicate/cancellation
rejection.

## Lean execution-to-call theorem

The follow-up Lean module `E7CJointAdmissionExecution.lean` defines the
selected normal-path call sequence as `AdmissionStep` and
`ModeledNormalExecution`. Its theorem
`modeled_normal_execution_yields_call_derivation` proves that a run reaching
the equality-guard true branch yields #135's `NormalReturn` derivation;
`modeled_normal_execution_exact_rows` composes this with the existing all-list
Lean theorem. The executable counterexample theorem
`changed_rows_cannot_take_modeled_normal_return` proves that a changed
serialized row list cannot follow the modeled normal-return branch.

This is an operational-to-call proof for the Lean semantics. The `hparse`,
`hjoint`, and `hrows` equations in `AdmissionStep` state the mathematical
results of the corresponding calls; `hguard` is a premise recording the modeled guard outcome on
the successful control-flow branch. It is not an observation of CPython
execution. The source AST pin plus the CPython operation premises above still
must establish that the running interpreter produces those equations and
values. In particular, the Lean input is already
typed `WireRow` and therefore does not model raw JSON integer numerator and
denominator decoding, exact built-in object identity checks, or the Python
exception boundary. The theorem is conditional on canonical graph input and
normal return. It is not a proof of all-input CPython adequacy.

## Exact theorem boundary

Covered by the Lean results: the generated admission program, every finite
ordered list of canonical typed `WireRow`, arbitrary typed rational
coefficients, arbitrary normalizer, and every derivation whose serializer
equality guard returns true. The new execution theorem derives #135's call
relation from the selected mathematical execution of parser, Joint, serializer
and equality-guard operations.

Not covered: malformed input and its precise exception behavior; raw JSON
numerator/denominator decoding and graph construction before reaching
`WireRow`; the operation-to-CPython refinement premises above; nontermination, host-resource
failure, asynchronous interruption, and mutation or rebinding; source event
semantics and first-stage resource charging; independent IR execution under
the separate `/0.5` and `/0.6` byte bounds; stage-two execution and charged
failed second append; general Python/IR-to-Lean correspondence.
