## Exact statements still to prove

Let `Admit(d)` mean the actual `e7c_eecq_two_stage_b1.admit(d)` succeeds;
let `Encode(d)` be the exact ordered `WireRow` map, policies and budget
defined by `e7c_eecq_two_stage_exact_codec.py`. Let `Obs(d,r)` be its
`observation(d,r)` function, including validated event serialization.
Let `LeanRun(Encode(d))` be `E7CEECQTwoStageOperational.run` on the encoded
rows, policies and budget, transported into the same observation record.

The intended code semantics is a still-to-be-formalized `⇓Py,ρ` evaluation
relation for the pinned Python entry points and their imported helpers, with
CPython 3.12 as the current execution target. Its environment `ρ` must fix
the interpreter version and builtins, module identities,
constants and callable bindings; calls use no injected transition sink or
dynamic replacement. The relation must define exceptions, canonical JSON,
exact `int`/`Fraction` operations, iteration, copies and event serialization.
No such complete formal semantics or checked translation has yet been supplied.

**Source partial-correctness theorem (unproved):** for every `d` with
`Admit(d)`, and every result `r` for which the actual Python evaluation
`evaluate(d) ⇓Py,ρ r` terminates normally, there exists an observation `o`
such that `Obs(d,r) ⇓Py,ρ o` and `o = LeanRun(Encode(d))`. This asserts
that the observation projection is defined for every normal result; it does
not infer termination from admission. A separate **totality theorem**, if
claimed, needs quantified upper bounds on the executed work and allocations,
host time and memory at least those bounds, adequate recursion and integer
conversion limits, and no externally induced interruption or I/O failure.
Those bounds and host-premise adequacy are open.

**IR partial-correctness theorem (unproved):** for every `d` with `Admit(d)`
and a separately declared `IRPackageBound(d)`, and every normal execution
`lower(d) ⇓Py,ρ p` and `execute(p) ⇓Py,ρ q`, require
`parse(serialize(p)) ⇓Py,ρ p` and an observation `o` with
`Obs(d,q) ⇓Py,ρ o` and `o = LeanRun(Encode(d))`.
`IRPackageBound(d)` must cover canonical encoding and the 1,000,000-byte
limits of **both** the nested /0.5 and outer /0.6 serialized packages,
independently of the claimed outcome. The nested bound does not imply the
outer bound; source admission imposes neither bound. The outer package
duplicates source, nested package and witnesses. Proving lowering and execution total
under that premise and explicit host resources is a separate obligation.
The package bound cannot be inferred from `Admit(d)`; the counterexample
below shows why. A narrower admitted subset or typed lowering failure for
the larger source domain remains a design choice.

Equality includes terminal outcome and its stage, the *complete* exact
correlated three-way rational partition on success, ordered events with
their validated wire fields, charged steps and progress, first exclusions,
second exclusion prefix and `secondStarted`. Resource exhaustion has no
partition. In particular, a charged second attempt whose append fails has
`secondStarted = true`, unchanged ledger and incremented steps.

## Bounded code-facing increment

`e7c_joint_control_flow_pin.py` pins the normalized Python AST of all four
actual entry points (source/IR first stage and source/IR second stage). A
mutation of a guard, visit order, child call, second-start assignment or
serialization call fails. The existing transition-site audit additionally
checks the charge/append probes, including second-attempt ordering and child
sink forwarding. The first-stage regression executes both actual paths for
success, unsupported, undetermined, zero steps, failed attempt append and
failed row append. It compares the full observations including rational
portions and ledger/progress. `E7CJointFirstCodeSkeleton.lean` defines a
fuelled first-stage child machine and proves zero fuel, charged but failed
attempt or row append, both policy stops and an all-list exact partition,
ordered event ledger and step count at an exact sufficient budget. This is a
formal first-stage control-flow
*model*, **not** a verified translation of the Python evaluator or IR
executor. The AST and differential checks are finite controls, **not** a verified
translation or an all-input theorem. The AST pin covers those entry-point
bodies, but not `admit`, `joint`, `rows`, `restrict_joint_absent`, canonical
serialization, the Python interpreter or dynamic dependency replacement.

The source admission counterexample has one valid row with a 600,000-character
tag and zero steps. The source admits it and returns `resource_limit`; the
first IR `lower` fails its million-byte serialized-package bound. A
second, independent counterexample has one `1/2` row with a 200,000-character
tag and zero steps: source admission and `resource_limit` evaluation succeed;
the nested /0.5 package is 402,488 bytes and lowers, while the outer /0.6
candidate is 1,006,894 bytes and lowering rejects it. Both observations are
pinned by the selected source/IR regression; they establish the necessity of
two size premises, not their adequacy for all normal host executions. Thus the
unqualified IR theorem for *all* source-admitted documents is false.

## Next bounded control-translation candidate

`e7c_joint_first_control_translation.py` reads the pinned actual function ASTs,
checks first-stage resource and policy guards, two charge sites, row iteration
and predicates, and extracts a common instruction schedule. The full AST
fingerprint rejects changed unexamined statements. A separate wire-level
machine executes that schedule on ordered exact Joint rows. The boundary
matrix checks it against **both actual functions**, including serialized
terminal/progress/ledger records, witness claim and every emitted charge/append
transition. It covers sizes 0–3, policy failures and ready, and every budget
in `0..size+2`; zero-step and charged failed append are included.

The schedule is manually specified and the Python extractor/interpreter is
not verified against CPython semantics. In particular, `admit`, canonical
serialization, `restrict_joint_absent`, IR `lower`/`parse`, exception/host
behavior, and unbounded tags or integers do not follow from these finite
checks. This candidate is **not** the checked translation and all-input
simulation required to close either theorem above. The next proof needs an
explicit semantics or independently justified verified translation of these
actual calls, including the source success partition and IR's exact rational
`amounts` check, followed by stage-two composition.

## First-stage relational proof candidate

`E7CJointFirstExecutionRelation.lean` now defines an inductive execution
relation for the first attempt and each row. Its rules charge before append,
stop without inspecting an unaffordable row, retain the exact correlated row
and rational coefficient, and distinguish resource, unsupported, undetermined
and completed outcomes. `rows_sound` and `first_sound` prove for **every**
derivation in this relation that its model observation equals the existing
fuelled Lean machine. `rows_complete` and `first_complete` construct a
derivation for every encoded row list, policy and budget; this completeness
concerns the **Lean model domain** only. `under_helper_contract` exposes the
ordered input-row transport premise. It does **not** prove that actual Python
or IR runs have a derivation in this relation, or that the concrete helpers
satisfy their proposed contracts.

The remaining bridge is explicit: check the *entire* pinned AST against the
relation (including nested calls and exception paths), justify CPython's
operation semantics, prove `admit`/`joint`/`rows` preserve exact ordered input,
`restrict_joint_absent` returns the same partition, canonical row keys and
event/witness serialization preserve observation, and IR lowering and parsing
preserve admitted inputs subject to both package bounds. Then compose with
stage two. This model proof alone is **not**
a checked implementation translation or all-input source/IR-to-Lean theorem.

## Direct canonical-sublist construction: merged bounded correction

The selected provisional adapter now constructs both children as
`Joint(source.arity, retained)` and `Joint(source.arity, excluded)`, using
`tuple` comprehensions over `source.terms`. The old calls to `joint`, which
recollected coefficients, have been removed from this restriction path. For
any already canonical `Joint`, a filtered subsequence retains original row
objects and exact fractions, arity and nonzero coefficients. The Lean
`canonical_portions_order` theorem proves that an arbitrary pairwise strict
order survives both complementary filters. For the constructor's tuple of
`Config.identity()` keys, strict order entails unique support; hence these
subsequences satisfy its sorted-and-unique check. The existing
`selection_transport` theorem carries the row and coefficient equality for
all encoded lists without a normalization hypothesis. This closes the
*mathematical normalization premise on this selected path* by removing that
operation, rather than asserting that its old implementation preserves rows.
The AST checker pins the direct return and exact comprehension sites, and
source/IR replay tests check that the changed path behaves as expected.

**Remaining running-code link:** the Lean proof does not establish the
semantics of CPython `tuple` comprehensions, dataclass construction,
`Config.identity()`, sorting, or the full `Joint.__post_init__` and entry
point calls. Admission's normal-return claim, source and IR transition
simulation, canonical JSON, event and witness serialization, exception and
host behavior, and IR package bounds remain open. No all-input Python/IR
implementation theorem is claimed by this change. The next proof increment
must provide a defined execution semantics or independently justified
translation of the constructor and first-stage helper calls, then compose
with the existing Lean relation.

## Direct retained-child construction: merged bounded correction

The source two-stage evaluator previously re-parsed the first child's
retained wire rows into `Config`/`Fraction` values and called `joint`, which
re-collected and sorted them before charging the second attempt. It now
filters the already admitted canonical typed Joint directly and compares its
serialized retained rows against the **actual first-stage child return**. A
normal continuation therefore passes an explicit equality guard at this
boundary, without reconstructing a joint from marginals or re-collecting
coefficients. Each second-stage row event likewise uses a single-row direct
`Joint` constructor. A forged child coefficient fails the guard in the new
regression. The separate source and IR functions retain their independent
traversal; this change does not prove CPython executes either according to
the Lean relation. Admission can traverse every row before a zero-step
evaluator returns `resource_limit`; zero fuel prohibits evaluation row visits,
not admission work. Event and witness serialization, constructor semantics,
IR parsing and source-to-Lean refinement remain open.

## Guarded admission postcondition: bounded proof candidate

The running first-stage `admit` ends in three adjacent statements inside its
exception boundary: `value = joint(parsed, arity=2)`; reject when
`rows(value) != source["rows"]`; return that same `value`. The selected
helper-site checker now verifies this exact suffix, a single normal return,
and the full pinned AST of the preceding row admission and helper bodies.
On a normal return, with stable source data and fixed callable bindings,
ordinary CPython branching and structural list/dict equality imply the
**postcondition** `rows(returnedJoint) == source["rows"]`. This implication
is independent of how `joint` collected and sorted parsed coefficients:
if it changes the observable row sequence, the guard rejects the result.
`E7CJointFirstHelperSelection.admitted_rows_exact` proves the guard's
all-list value implication, and `guarded_admission_selection` transports
exact pairs, their row order and rational coefficients to the first-stage
Lean selectors. A regression replaces `joint` with hostile implementations
that change a coefficient or reverse the row order; neither returns normally
from admission.

This is a conditional code-level **normal-return postcondition**, not a
verified interpreter translation or the full implementation refinement.
The CPython control/equality semantics, no concurrent source mutation,
fixed helper identities, normal termination and exact Python `rows` to
`WireRow` encoding are the stated premises. In particular, the guard does
not prove the serializer returns a faithful representation of the typed
`Joint`, that invalid inputs are rejected correctly, or that an unmodified
`joint` implementation always terminates. Its constructor, `Config`,
`Fraction`, serialization, two-stage event, IR and witness correspondences
remain open. For IR, the nested `/0.5` and outer `/0.6` size bounds remain
independent premises. A failed second append still requires a step charged,
`secondStarted = true`, and no second-attempt ledger append.

## Required proof path

1. Define a small-step language for the actual first-stage subset, including
   Python admission/exception boundaries, row iteration, exact fractions,
   policy guards, `steps += 1` before ledger append, copying and event
   serialization. Supply a checked translation of the pinned AST into that
   language and justify the translation against the executed Python code.
2. Prove its first-stage source and IR execution simulations for all admitted
   rows and resource bounds: zero-step, failed attempt append, unavailable
   capability, unresolved obligation, every row, failed row append and
   complete partition. The present Lean `run` lemmas prove the abstract
   budget cases; they do not discharge the actual-code link.
3. Prove the source first-stage child return is preserved as a correlated
   Joint on entry to stage two and that the IR's parsed child result is the
   same encoded value. Then prove second-stage simulation, including failed
   second append and `secondStarted`, and finally compose the two theorems.

No theorem about supplied `Trace` certificates or this AST pin establishes
what every running Python program does. The EEC-Q component remains
**covered with an open link**, not **complete**. CI passing is not semantic
acceptance or a claim about other profiles/products.
