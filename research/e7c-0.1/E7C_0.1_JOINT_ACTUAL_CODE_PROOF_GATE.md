## Exact statements still to prove

Let `Admit(d)` mean the actual `e7c_eecq_two_stage_b1.admit(d)` succeeds;
let `Encode(d)` be the exact ordered `WireRow` map, policies and budget
defined by `e7c_eecq_two_stage_exact_codec.py`. Let `Obs(d,r)` be its
`observation(d,r)` function, including validated event serialization.
Let `LeanRun(Encode(d))` be `E7CEECQTwoStageOperational.run` on the encoded
rows, policies and budget, transported into the same observation record.

**Source theorem (unproved):** for *every* `d` satisfying `Admit(d)`, the
actual call `e7c_eecq_two_stage_b1.evaluate(d)` terminates normally,
`Obs(d,evaluate(d))` is defined, and
`Obs(d,evaluate(d)) = LeanRun(Encode(d))`.

**IR theorem (unproved):** for *every* such `d` satisfying an additional
declared `IRLowerable(d)` premise, the actual `p = lower(d)` succeeds,
`parse(serialize(p)) = p`, `execute(p)` terminates normally, and
`Obs(d,execute(p)) = LeanRun(Encode(d))`. `IRLowerable` must be stated as
bounded size and successful canonical encoding of both nested first-stage
and outer packages, independently of the claimed observation. It cannot
be silently inferred from `Admit(d)`. The counterexample below shows why.
Proving `IRLowerable` for a narrower admitted subset, or returning a typed
lowering failure for the larger source domain, remains a design choice.

Equality includes terminal outcome and its stage, the *complete* exact
correlated three-way rational partition on success, ordered events with
their validated wire fields, charged steps and progress, first exclusions,
second exclusion prefix and `secondStarted`. Resource exhaustion has no
partition. In particular, a charged second attempt whose append fails has
`secondStarted = true`, unchanged ledger and incremented steps.

## Bounded code-facing increment

`e7c_joint_control_flow_pin.py` pins the normalized Python AST of all four
actual entry points (source/IR first stage and source/IR second stage). A
mutation of a guard, visit order, child call, second-start assignment or
serialization call fails. The existing transition-site audit additionally
checks the charge/append probes, including second-attempt ordering and child
sink forwarding. The first-stage regression executes both actual paths for
success, unsupported, undetermined, zero steps, failed attempt append and
failed row append. It compares the full observations including rational
portions and ledger/progress. These are finite controls, **not** a verified
translation or an all-input theorem. The AST pin covers those entry-point
bodies, but not `admit`, `joint`, `rows`, `restrict_joint_absent`, canonical
serialization, the Python interpreter or dynamic dependency replacement.

The source admission counterexample has one valid row with a 600,000-character
tag and zero steps. The source admits it and returns `resource_limit`; the
first IR `lower` fails its million-byte serialized-package bound. Thus the
unqualified IR theorem for *all* source-admitted documents is false.

## Required proof path

1. Define a small-step language for the actual first-stage subset, including
   Python admission/exception boundaries, row iteration, exact fractions,
   policy guards, `steps += 1` before ledger append, copying and event
   serialization. Supply a checked translation of the pinned AST into that
   language and justify the translation against the executed Python code.
2. Prove its first-stage source and IR execution simulations for all admitted
   rows and resource bounds: zero-step, failed attempt append, unavailable
   capability, unresolved obligation, every row, failed row append and
   complete partition. The present Lean `run` lemmas prove the abstract
   budget cases; they do not discharge the actual-code link.
3. Prove the source first-stage child return is preserved as a correlated
   Joint on entry to stage two and that the IR's parsed child result is the
   same encoded value. Then prove second-stage simulation, including failed
   second append and `secondStarted`, and finally compose the two theorems.

No theorem about supplied `Trace` certificates or this AST pin establishes
what every running Python program does. The EEC-Q component remains
**covered with an open link**, not **complete**. CI passing is not semantic
acceptance or a claim about other profiles/products.
