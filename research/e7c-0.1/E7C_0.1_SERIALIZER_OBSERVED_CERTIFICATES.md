## Actual execution path

`observe` calls the unchanged running `e7c_eecq_joint_restrict_b1.rows` helper.
It does not call the selected AST interpreter, replace source helpers, or
change product code. The observer uses CPython's current-thread profiling
interface to capture `_graph`, `_row` and `rows` frame entry/return payloads.
Normal completion is determined by the direct helper call returning, not by
the mere presence of a profiler `return` event.

Python's official documentation notes that profile return events can also be
reported when an exception is set, and that profiling is thread-specific:
<https://docs.python.org/3.12/library/sys.html#sys.setprofile>.
Frame events do not observe every attribute, container operation, opcode or
interpreter step. They are **not** #159's primitive operation trace.

`freeze_manifest` checks pinned helper ASTs, generated source expressions,
the live functions against freshly compiled source code images, their native
global/builtin bindings, and live historical edition/blob constants. The
manifest records exact CPython micro-version/build, cache tag, optimization,
platform, executable hash, Fraction module hash, source file hashes and
helper code hashes. Installation filenames are removed only from code
fingerprints, not from the runtime's declared version/build.

Each capture requires its caller's frozen exact manifest. A different host,
code image or binding is unsupported. The implementation currently admits
the CPython 3.12 family; each report pins its **individual exact runtime**.
This is not a claim that all 3.12 micro-versions have proved equivalent.

The observer requires a session with no existing trace/profile hook and one
reported Python thread. It checks the input snapshot, source/bindings and
thread/trace state again after the call and verifies complete helper site
order. These checks do not prove uninterrupted global stability or rule out
transient mutation, hidden native threads, malicious runtime behavior or
observer tampering.

## Outcomes and bounded carrier

Edition: `E7C-serializer-observation/0.1-provisional`. This research envelope
is separate from the EEC-Q product outcome and wire editions.

| Observation status | Meaning |
|---|---|
| `observed_normal` | Direct helper return, selected snapshots and complete frame order recorded; certificate still requires kernel checking. |
| `invalid_input` | Rejected observer input or bounds, including objects outside its exact native selected carrier. |
| `resource_limit` | Accounted row/event/bit/byte limit, or observed host MemoryError; no output certificate is returned. |
| `unsupported` | Runtime/code/binding mismatch, existing instrumentation or reported multiple threads. |
| `abnormal` | Observed helper/instrumentation exception, SystemExit or KeyboardInterrupt; not a normal result. |
| `undetermined` | Stability/capture failure, missing frame order, unsupported normal output snapshot or failed profiler restoration. |

The selected carrier uses exact native binary Joint, Config and Fraction
objects, canonical unique ordered support, nonzero reduced signed fractions,
and Unicode-scalar string tags. It is stricter than arbitrary CPython objects
and is not a proof of the original admission procedure.

Maximum rows: 64; maximum fraction/raw integer bit length: 256. Default
accounted helper-event budget: 386 (`6 * 64 + 2`). Default reported packet
byte budget: 262144. Snapshot nesting has its own bound of eight. Bounds
apply to the observer's accounted work/data. They do not bound peak memory,
wall time, rational computation or unobserved host execution. A byte check
occurs after native JSON encoding has allocated its bytes. No EEC-Q charged
steps, budgeted ledgers or failed-append rules are inferred from these caps.

When a cap or failure occurs, partial frame evidence may be retained, but
there is no `output` field or partial successful certificate. Profiler
restoration is attempted after every installed observation.

## What Lean checks

Four saved actual normal reports cover empty, diagonal, crossed, and signed
fraction/control-character cases. The JSON retains the original exact host
manifest. Other-host replay compares portable reported mathematical content;
it does not pretend to rerun that historical micro-version.

The exporter preserves the supplied input, output and every frame payload as
literal Lean data. It uses no supplied arbitrary Lean code and rejects
malformed/injected numeric expressions; string quoting follows Lean's escape
grammar (<https://lean-lang.org/doc/reference/latest/Basic-Types/Strings/>).
Export itself is not validation. A forged report is allowed to produce a
well-formed file with a false equality; the kernel must reject that proof.

The concrete `CaptureValid` proofs check two equalities:

1. Reported output equals the exact ordered encoding of the reported typed
   rows, including each full graph pair, null/string tag and rational pair.
2. Reported frame ledger equals the complete ordered helper plan, with both
   graph coordinates and each helper's reported result present.

The plan length is proved to be `6 * rows.length + 2`. A checked reported
output yields a **modeled** #159 operation derivation and unique-key/fuel
facts. This derivation is constructed mathematically; it is not claimed to
be the actual CPython primitive execution.

The hosted runner generates certificates from fresh live execution under
its own frozen manifest, checks them using pinned Lean, and requires kernel
rejection of four changed reports: unreduced output `2/4` in place of `1/2`,
null changed to empty string, an omitted frame, and reordered output rows.
Import/compiler/runtime failures are not counted as successful forgery
rejections. Original raw admission pairs remain separate from native
Fraction snapshots; this package does not prove the raw admission guard.

## Trust boundary and remaining proof

Kernel checking establishes mathematical agreement of **reported literals**.
It does not authenticate their runtime origin, establish source truth or
prove that the observer faithfully captures values. A fabricated report
that contains mathematically matching data can pass; hashes and a runtime
manifest are identity records, not authenticity or adequacy proofs.

Native value denotation, manifest/hash/compiler fidelity, actual frame-event
delivery, the collector/exporter, uninterrupted bindings and ordinary host
behavior remain trusted. These are not silently replaced by the certificate
equalities. Admission/Fraction/Config/Joint construction and aggregation,
final Python equality, and actual exceptions/resource behavior retain their
separate open semantic links.

The next general obligation is still that each admitted normal running
CPython serializer execution supplies #159's local relations and complete
ordered primitive visits under non-circular operation-level premises.
Independent IR under `/0.5` and `/0.6`, stage two and the charged failed
second append remain later gates. EEC-Q and E7C remain incomplete.
