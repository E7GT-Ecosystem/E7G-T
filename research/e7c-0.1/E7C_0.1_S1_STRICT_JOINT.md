The new `strict_union` term accepts an exact binary FG3 Joint whose two
coordinate types match. It returns a terminal `Outcome[State,strict-edition]`.
Each supported pair must have matching graph tags. When compatible, the
operation unions its edges and carries the pair's single signed rational
coefficient once. Result collisions are collected and cancellation is exact.
If any supported pair has different tags, the entire operation returns
`domain_error` and no state, even if earlier pairs were compatible or the
offending coefficient is negative. The ordered ledger records the first
offending supported index and actual visit count. A zero joint succeeds with
a zero state. Raw rows are fully validated before input cancellation; rows
that cancel out are not in the support being checked.

The existing finite resource bound is charged before examining a pair. If
the bound runs out before reaching a bad pair, the terminal is
`resource_exhausted` with no partial value. The independently coded replay
checks this ordering and rejects invented partial successes, ledgers and
boolean-for-integer substitutions. The earlier S1 edition does not admit
this term; its existing programs and witness edition are preserved.

This is a selected FG3 union rule, not a general gluing procedure. It does
not admit arbitrary graph signatures, disjoint namespaces, wire-choice
relations, filters, quotation, phase or WPC, nor prove a semantic theorem.
No canonical, profile, product, schema, data or API migration occurs. Next
gate: formal S1 correspondence and preservation obligations, then remaining
WP5 adapter coverage and WPC under its native identity contracts.
