## Checked compiler image

The translator first applies #160's frozen runtime/source/code/binding
checks, then disassembles the **running** `_graph.__code__`, with
`adaptive=False`. It requires the selected CPython-3.12 frame layout,
argument/local/constant/name tables, flags (including the source's future
annotations flag), stack size and empty exception table. Exact runtime and
source/code hashes are retained in the saved image manifest.

Every non-CACHE instruction and operand becomes one Lean instruction. NULL
call setup and non-method LOAD_ATTR flags are checked explicitly. No jumps,
exception handlers, unknown opcodes or generic Python calls are supported.
The full cache-bearing image and offsets are recorded separately; removing
CACHE entries must produce exactly the complete translated stream. The
generated Lean file is checked against the live image on each hosted run.

The selected image has ten instructions: RESUME, LOAD_GLOBAL, LOAD_FAST,
LOAD_ATTR, CALL, LOAD_FAST, LOAD_ATTR, LOAD_CONST, BUILD_CONST_KEY_MAP and
RETURN_VALUE. LOAD_CONST supplies the ordered unique pair `edges`, `tag`.

CPython's official documentation describes bytecode as version-dependent
implementation detail, with cache entries and adaptive specialization:
<https://docs.python.org/3.12/library/dis.html>.
This translation checks the **unspecialized code image**, not the adaptive
instruction path actually dispatched. No equivalence between specialized
and unspecialized execution is proved. Exact runtime pins are records,
not semantic or authenticity proofs.

## Selected machine and mathematical result

The stack stores values, the NULL sentinel, the selected list constructor
and a tuple of keys. Each instruction performs its declared stack action;
CALL requires the value/constructor/NULL order. The constructor visits every
modeled tuple cell in order and appends it to a fresh modeled list. The
prefix theorem derives the complete result of that construction for every
finite list, so no finished list-copy equality is supplied as a premise.
This fold is a mathematical operation specification, not a claim that
CPython uses that allocation strategy or append loop.

BUILD_CONST_KEY_MAP consumes two values in stack order and assigns them
to the ordered unique keys. Duplicate-key objects are outside this selected
machine; CPython's generic overwrite semantics are not modeled. RETURN_VALUE
requires one value and must be the final instruction. No missing, repeated
or reordered instruction is silently accepted as an equivalent program.

The all-input graph theorem assumes only two local read contracts: `edges`
and `tag`. It derives the exact output from the checked program and the
declared instruction semantics, without a completed helper result, completed
trace or list-copy result premise. It covers every WireGraph edge list and
optional string tag, including order and duplicates. The original source
admission remains narrower: this theorem does not expand its graph registry,
canonical order or admitted row cap.

The graph normal-return result composes into #159's **modeled** GraphNormal
relation using the ordered-copy operation. Changed outputs have no selected
machine normal derivation. Malformed stack, missing sentinel and early-return
examples reject. `none` is modeled failure; it does not classify CPython
exceptions, unsupported operations, nontermination or resource interruptions.

The machine executes a finite instruction list structurally. Ten modeled
instructions are not ten CPython charged steps, nor an allocation, memory,
wall-time, rational-growth or EEC-Q budget bound.

| Native tuple iteration, `list` construction/allocation and exception behavior | unproved; not discharged by the fold theorem |

| Raw admission, final Python equality and host completion/resource behavior | separate open links |

This is a compiler-image refinement increment. It does **not** eliminate
the native CPython list-copy adequacy premise, and does not replace it with
a whole-helper result assumption. #160's reported-run certificates remain
finite evidence with their separate capture/denotation trust boundary.
The remaining all-input obligation is that pinned CPython execution supplies
these opcode and native operation semantics under non-circular local premises.
EEC-Q and E7C remain incomplete.
