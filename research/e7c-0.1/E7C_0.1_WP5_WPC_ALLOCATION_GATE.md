The adapter is independently coded against the finite WPC source example.
`Whole` is semantic state; `Portion` has a distinct occurrence identifier,
actual local value and `Representation`; `Presentation` carries the exact
manifest and history. `constitute` checks coverage, constitutes from the
actual local values, then requires each representation to decode to that
same whole. Equal encoded payloads therefore never collapse occurrences.
Materialisation and constitution round-trip for the canonical admitted
finite domain; an encoded representation is not itself a semantic whole.

`Proposal` includes the full canonical source identity. `reconcile` checks
the whole batch and returns an explicit `Candidate(base, proposed, events)`;
conflicting writes and a jointly excessive allocation reject the entire
batch. `membership_candidate` retains the base, histories and retired
occurrence check, and refreshes all representations only when the proposed
whole is separately materialised. Neither API commits a successor.

Five differential tests compare the adapter with the pinned reference model:
ten finite initial wholes and thirty exact portion round trips, missing and
duplicate coverage, stale or changed payload conflict, joint incompatibility,
candidate lineage, proposal order and deduplication, changed membership,
authority and retired occurrence rejection. The workflow runs these tests
and the reference model's own tests. Comparison covers only this selected
model; malformed external JSON and arbitrary profiles are not imported.

This package does not add WPC constructors to the accepted E7C-B1 grammar,
prove a calculus preservation/adequacy theorem, implement a complete
constitution outcome algebra, SR0–SR3, contextual expression, distributed
commitment, or WPC conformance. The next gate is a versioned E7C WPC module
sort and operational/denotational interpretation, followed by the remaining
WP5 adapters in roadmap order. Published v0.12.1/RGP2 stays canonical;
the WPC/0.2 source remains a separate experimental draft.
