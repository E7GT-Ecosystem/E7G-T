# RGP/0.2 contextual expression: finite typed example (review candidate)

Baseline: main `babc31f00ed32b899a6000ae7b9bdedb084aeeb6`
(PR #112 merge). Source authority for this candidate is the v0.13/RWP1
draft X.18 R.1–R.2, R.5.4.3 and its text-identical inheritance in the
v0.14/REC1 draft, pinned by `e7c_rgp_successor_audit.py`. Published
v0.12.1/RGP2 remains canonical RGP/0.1, with no automatic conversion.

`rgp02_expression_b1.py` implements one **text-derived read-only** finite
interpretation of `Expresses`. Its `Whole`, SR4 `Portion`, complete `Context`,
registered `ExpressionRule`, `LocalExpression` and typed `Outcome` are
different sorts. The admitted whole is a bounded UTF-8 exact string-field
record for either v0.13 or v0.14. The portion stores its canonical whole
payload with an occurrence and codec edition; decoding checks the exact
whole digest and source edition. The local expression projects selected
fields only when the rule's kernel/source editions and role/access contract
are admitted and enough field
budget exists; it carries the source identity, occurrence, complete context,
rule edition and an explicit lost-field account. A successful expression
is never returned as a `Whole` or as a self-contained encoded `Portion`.

Unsupported roles and state-changing/generative modes return `unsupported`;
a missing selected field is `undetermined`; a mismatched source edition is
`domain_error`; insufficient field budget is `resource_limit` with no
partial successful expression. Malformed or tampered SR4 input fails
admission. These are edition-specific **local choices**, not an assertion
that the full RGP/0.2 outcome algebra has been formalised.

Three bounded test methods exercise both draft kernel editions, exact SR4
round trip, two distinct occurrences with the same visible expression,
different whole sources with the same visible field, every terminal branch,
and payload, digest and edition tampering. Conventional comparison is direct
finite dictionary field selection and exact JSON round trip; there is no
independent executable RGP/0.2 reference `Expresses` API to compare. The
existing RGP/0.1 finite adapter remains a different edition and model.

**Covered with an open link, not complete:** the tests do not establish a
source-to-E7C fidelity theorem, general context-dependent expression rules,
generation or state change, overlap coherence, WPC all-portions agreement,
relative reconstruction, a general resource model or Python/Lean
refinement. In particular, equal local output never proves equal whole,
and individual SR4 round trips across different source editions do not
prove WPC/0.1 cross-portion coherence. Next: formalise this typed judgement
and denotation in Lean, prove its provenance/loss/resource properties, then
add an independent v0.13/v0.14 source interpretation or explicitly record
that no such reference exists. The remaining changed RGP clauses retain
their separate obligations.
