## Statement path in scope

The normal branch of `admit(source)` executes, in source order:

1. `require_canonical_json(source)`;
2. exact top-level dict/key/metadata checks and exact policy dict/key/type checks;
3. exact rows list/limit checks, then each row's exact dict/key/list/arity checks;
4. exact numerator/denominator `type(x) is int`, positivity and nonzero checks;
5. `Config(tuple(edges), tag)`, followed by `_graph(config) != rawGraph` rejection;
6. `Fraction(numerator, denominator)` and append of each parsed ordered pair;
7. `joint(parsed, arity=2)`, whose helper visits every row, updates an insertion-ordered
   dict keyed by tuples of Config, adds Fractions, filters zero totals, sorts by
   `Config.identity()`, materialises terms, and calls `Joint`;
8. `rows(value)`, whose list comprehension calls `_row` and `_graph`, then
   reads Fraction numerator and denominator;
9. the final `rows(value) != source["rows"]` branch. Fall-through returns
   `value`; a raised admission error, other exception, nontermination, or
   resource interruption is a different execution outcome.

The operation steps above are pinned by AST, and the semantic components are
represented by #146's JSON decoder and the earlier Lean operation models. This
draft checks the critical CPython equality primitive against #146's current
RawJson representation before claiming a composed theorem.

## Discovered boundary

Python dict equality ignores insertion order of keys. #146 models an object as
`List (String × RawJson)` and its guard premise uses Lean structural equality
on that list-backed AST. These are different relations. The Lean counterexample
in `E7CJointCPythonEqualityBoundary.lean` exhibits equal mappings with
different field sequences. The focused host regression executes the pinned
`admit` helper with reordered row-object keys and confirms normal admission.

Consequently, normal fall-through of the pinned Python guard supplies
order-insensitive Python value equality. It does not in general supply
`rawRowsOutput = document.rawRows` in #146's structural RawJson equality.
The proposed exact CPython-to-#146 trace cannot be proved for all admitted
inputs until the representation/guard link is repaired (for example, make
object equality extensional in the RawJson model, or prove and enforce a
canonical field-order precondition). The pinned code does not enforce the
latter.
