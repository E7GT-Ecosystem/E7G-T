# Start with the decision, not the terminology

E7G-T is a geometry-first reasoning framework for situations where a view, summary, translation, dashboard, AI answer, interface, measurement, or report stands in for something richer.

> The practical question: What is being modelled, what does the current representation preserve or lose, which differences matter for this inquiry, and what is the next responsible move?

This kit helps you:

- name the actual entity and decision;
- separate the source from the visible view;
- record what the view preserves, loses, or may distort;
- define which differences matter for the intended use;
- decide whether the view is sufficient;
- classify, return to source, obtain another view, repair the criterion, or stop.

## Use the smallest profile that changes the next move

| Profile | Use it when | Typical output |
| --- | --- | --- |
| E7-Line | The basis is obvious and the risk is limited | One disciplined paragraph |
| E7-Check | Routine QA or review needs a visible audit trail | A compact structured check |
| E7-Analysis | The decision is consequential, disputed, or reusable | A full representation-and-phase account |

This kit focuses on E7-Line and E7-Check.

# What E7G-T is - and is not

## Proper role

E7G-T can help frame, inspect, compare, classify, navigate, document, teach, lint, and route reasoning toward a responsible next move.

It is especially useful when:

- the visible representation may be lossy;
- several source configurations could produce the same view;
- those possible sources may support different operational decisions;
- an edit or transition may cross a material boundary;
- operation order or path choice may matter;
- a formal-looking output risks being mistaken for proof, authority, or completed work.

## Limits

E7G-T is not:

- established mathematics as a whole;
- empirical physics or a Theory of Everything;
- a proof system;
- an authorisation or acceptance decision;
- evidence that a task was actually performed;
- a replacement for mature legal, medical, engineering, scientific, statistical, translation, or other domain methods.

> Use E7G-T to expose uncertainty and route the work. Do not use it to manufacture authority.

## The smallest-use rule

If a typo, standard test, direct source check, or ordinary domain rule already determines the action, use that method. Add E7G-T only when it makes a hidden representation, equivalence, boundary, or transition problem visible.

# The seven-step minimum workflow

## 1. Name the modelled entity

What real object, claim, document, system, state, or process are you analysing?

## 2. Separate context from inquiry

Context says what the terms mean. The inquiry says what decision you are trying to make.

## 3. Declare the operational boundary

What is included, excluded, and admitted for comparison?

## 4. Identify the current configuration or view

What can you actually see: source, translation, summary, dashboard, AI output, screenshot, test result, or interface state?

## 5. State what is preserved and lost

What survives into the view? What disappears? What may be distorted?

## 6. Define what counts as the same phase

Which differences are tolerated, and which protected condition must remain true for the intended use?

## 7. Make the next move

Classify, narrow, abstain, return to source, obtain another view, compare paths, repair the criterion, or stop.

> Compact cycle: construct -> represent -> project -> compare -> classify -> navigate -> verify -> rely or stop

# Choose the right route

E7G-T has two complementary routes. Use both only when the decision requires both.

| Your primary question | Route |
| --- | --- |
| What is being constructed or projected? | Extensional-projective |
| What does the representation preserve or lose? | Extensional-projective |
| Which richer sources could explain the visible view? | Extensional-projective reconstruction |
| Which configurations count as operationally equivalent? | Operational phase |
| Did a change cross a material boundary? | Operational phase |
| Does order or path change the protected result? | Operational phase |
| Can this view support a readiness or reliance decision? | Combined |

## The combined test

A visible view may be compatible with several richer source configurations. Ask:

1. Which materially distinct source candidates remain possible?
2. Which operational phase does each candidate belong to under the pinned criterion?
3. Do all supported candidates lead to the same classification?

| Phase spread in the view | Responsible response |
| --- | --- |
| One supported phase | Classification may be justified |
| Several supported phases | Abstain, narrow, obtain another view, or return to source |
| No admitted phase | Repair the model, boundary, or criterion |
| Unknown support | Do not overread the view |

# E7-Line: the one-paragraph check

Use E7-Line when the basis is clear and you need immediate orientation.

> For [inquiry], treat [subject] as [view/configuration] under [context]. Preserved/lost: [summary]. Same phase while: [protected condition]. Assessment: [same / different / undetermined / not applicable]. Next move: [action].

## Blank E7-Line

**Inquiry:**  
[Write the decision you are trying to make.]

**Subject and current view:**  
[Name the entity and what you can actually see.]

**Context:**  
[State the domain and intended use.]

**Preserved / lost:**  
[Record the relevant fidelity and omissions.]

**Same phase while:**  
[State the protected condition.]

**Assessment:**  
[Same / different / undetermined / not applicable.]

**Next move:**  
[Classify, verify, return to source, obtain another view, repair, or stop.]

## Stop condition

If the view supports materially different next moves, E7-Line is too small. Escalate to E7-Check.

# E7-Check: routine review

Use this profile for translation QA, document review, dashboards, software changes, AI outputs, or other routine decisions that need an audit trail.

## A. Frame

- **Entity:** What is actually being modelled?
- **Context:** What gives the terms their meaning?
- **Inquiry:** What decision must be made?
- **Intended use:** What will someone do with the result?
- **Boundary:** What is included or excluded?

## B. Representation account

- **Visible view:** What can the reviewer see?
- **Preserved:** What source properties remain available?
- **Lost:** What relevant information is absent?
- **Possible distortion:** What could be misleading?
- **Rival source candidates:** What materially different sources could still fit the view?

## C. Operational phase

- **Same phase when:** What protected condition must remain true?
- **Tolerated differences:** What can vary without changing the intended use?
- **Phase-defining conditions:** What difference would change reliance or action?
- **Support:** What evidence justifies the classification?

## D. Decision

- **Phase spread:** one / several / none / unknown
- **View sufficient:** yes / no / conditional / unknown
- **Next move:** classify / narrow / abstain / source return / another view / compare paths / repair / stop

# Worked example: translation used for legal action

## Scenario

An English translation states: "The applicant may submit the appeal within 14 days." The reviewer sees only the translation. The source-language sentence and governing procedure are not visible.

## Frame

- **Entity:** The source provision and its legally operative meaning.
- **Context:** A legal-administrative appeal procedure.
- **Inquiry:** Can the translation be relied on to determine whether submission is optional and whether the deadline is 14 days?
- **Intended use:** Decide whether and when to file.

## Representation account

- **Visible view:** One translated sentence.
- **Preserved:** Actor, action, appeal concept, and a 14-day interval.
- **Lost:** Source modal force, deadline trigger, calendar/business-day rule, surrounding exceptions, and procedural authority.
- **Possible distortion:** "May" could express permission, possibility, or a mistranslated obligation.

## Rival source candidates

| Candidate source meaning | Compatible with visible wording? | Reliance phase |
| --- | --- | --- |
| Filing is permitted within 14 days | Yes | Provisionally usable |
| Filing is required within 14 days to preserve rights | Yes | Action-critical |
| The authority may file, not the applicant | Possible if actor mapping is wrong | Unsafe |

## Result

The visible sentence spans materially different reliance phases. The view is not phase-sufficient for action.

> Next responsible move: return to the source, verify the modal, actor, deadline trigger, surrounding provision, and governing procedure. Do not calculate or act on the deadline from the isolated translation alone.

<!-- PAGE -->

# Why the worked example changes the decision

An ordinary style review might improve the English sentence without exposing the operational risk. E7G-T separates three questions:

## 1. Is the sentence fluent?

Possibly yes. Fluency is not the same as source fidelity or legal usability.

## 2. Is the visible translation compatible with more than one source meaning?

Yes. The missing modal, actor, and procedural context permit rival reconstructions.

## 3. Do those rival sources support the same next move?

No. Permission, obligation, and actor reversal create different operational phases.

## Boundary account

| Boundary | What it controls in this example |
| --- | --- |
| Model boundary | Whether surrounding provisions and procedural rules are included |
| Admissibility boundary | Which source meanings remain plausible enough to consider |
| Phase boundary | Where the permitted action or reliance status changes |
| Bridge boundary | Where linguistic analysis would become a legal conclusion |

## Typed-change discipline

Editing "may" to "must" is not a harmless style revision. It may cross a phase boundary because it changes the action signature. But the translation reviewer still cannot declare the legal rule without source and domain verification.

> The framework does not decide the law. It shows why the current view cannot safely support the intended decision.

# Run a small real-world pilot

Do not validate E7G-T by adding terminology. Test whether it changes or materially strengthens a real next move.

## Three-pass comparison

1. **Ordinary review:** Use your normal method.
2. **Projection review:** Record the entity, view, preservation, loss, rival reconstructions, and next move.
3. **Combined review:** Add the phase criterion, phase candidates, boundary status, path or order effects, and representative dependence.

## Pilot card

| Field | Record |

## Success criterion

The added phase layer earns its place when it changes or materially strengthens the next responsible move in a case where operational equivalence or boundary crossing genuinely matters.

It does not earn its place when it merely renames an ordinary correction, direct invariant check, or obvious source-return requirement.

# Continue from here

## Five useful next cases

- an AI answer used for a consequential recommendation;
- a translation involving modal force, identity, status, or legal effect;
- a dashboard tile used to infer readiness or health;
- a software refactor claimed to preserve behaviour;
- an interface state used to infer that work is complete.

## Keep a decision log

For each case, record:

- the visible representation;
- the intended decision;
- what was preserved and lost;
- the rival source candidates;
- the phase criterion;
- whether the view supported one phase or several;
- the action taken;
- what later evidence confirmed or corrected.
